# 本地 Agent 运行版范围

本轮依据用户 2026-09-21 新请求：将作品扩展为轻量本地服务，接入兼容 OpenAI 的 API，支持 1–3 个可运行 Agent。

阶段 4 原文件保持为冻结演示基线；新增 runtime/ 的网络通信、运行记录和测试独立验收，不以 P0 77/77 代替真实运行验收。

## 交付范围

- 单个 Node.js 进程 + 内置 SQLite，无 Docker、Redis、向量库或框架依赖。
- 案件调查、验证报告、日志排查三个可单独选择的 Agent 角色，共享一个串行执行队列，不做多 Agent 自动对话。
- 固定模拟业务数据；真实模型请求、模型选择工具、服务端执行工具并回传结果、持久化执行事件。
- 创建任务生成编号审批包，由用户确认授权后才能执行。工具白名单按角色和任务限定。
- 模型仅给建议；人工完成本地案件处置。超时、非法调用、数据缺失、取消或重启中断均保留证据。
- 最大 8 轮模型请求、20 次工具调用、单请求 60 秒、整任务 180 秒、单次输出 1500 token 上限。
- 仅监听 127.0.0.1；密钥只在服务端环境变量；模型配置缺失时阻止执行，不回退为伪造成功。

## 验收

1. 本地启动、页面访问、创建与审批任务、运行状态和事件查询可用。
2. 未批准不得调用模型或工具；越权工具、参数错误和无证据结论转待人工处理。
3. 真模型完成至少一次工具调用及基于结果的最终答复，才可宣称 Agent 真实联调通过。
4. 测试替身仅验证协议与错误路径，明确不能作为第 3 条证据。
5. 历史记录持久化；取消、超时、进程重启有确定的终态。
6. 14 页原型继续可访问，运行版和固定快照演示有明确标识。

实际用量以模型返回 usage 为准；缺失时记录未知，不虚构费用。
