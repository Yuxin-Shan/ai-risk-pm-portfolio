# 本地风控 Agent 运行版

个人作品，业务数据全部为虚构模拟。模型 API 请求、工具执行、任务状态和事件记录实际产生。该运行版独立于阶段 4 固定快照原型；不继承阶段 4 的 77/77 验收结论。

## 启动

需要 Node.js 24 或更高版本。本机已验证 Node.js 26.8.1 的内置 SQLite，无需 npm install、Docker 或额外数据库。

在仓库根目录：

```sh
cd runtime
cp .env.example .env
# 在本地编辑 .env，填写下面三个配置
npm start
```

然后打开 http://127.0.0.1:4317。Ctrl+C 停止服务。运行记录保存在 runtime/.data/runs.sqlite，重启保留；执行中的任务中断转人工，不自动重复请求模型。

- LLM_BASE_URL：供应商兼容 API 的根地址，一般以 /v1 结尾；程序追加 /chat/completions。以供应商文档为准。
- LLM_MODEL：支持 Chat Completions 工具调用的实际模型 ID。
- LLM_API_KEY：供应商密钥，仅服务端读取，不发送给浏览器。
- PORT：默认 4317。
- 也支持 OPENAI_BASE_URL、OPENAI_MODEL、OPENAI_API_KEY；LLM_ 配置优先。
- .env 与 .data/ 已忽略，不得提交真实密钥。

“模型已配置”只说明三个字段存在，不能证明连通；必须实际完成任务才算联调通过。没有配置时页面可访问并创建授权包，执行被阻止。运行中仅向配置的模型端点发送任务和模拟工具数据。

## 三个角色

| 角色 | 输入 | 实际工具 | 产出 |
|---|---|---|---|
| 案件调查 Agent | 3 条预置模拟案件之一 | 主体快照、交易、名单、关联查询 | 引用 sourceId 的调查建议 |
| 验证报告 Agent | 已结束的执行 ID | 执行记录、确定性检查计算 | 单次执行完整性报告 |
| 日志排查 Agent | 已结束的执行 ID | 执行记录、真实事件查询 | 带证据的故障分析 |

三个角色共用一个运行时、一个串行队列和模型配置，可只使用调查 Agent。角色有独立指令与工具白名单，不做无意义的相互聊天。后两个角色消费第一条任务的真实执行记录，不读取写死的“成功报告”。

## 演示闭环

1. 选择案件调查 Agent 和 SIM-CASE-001，创建任务。
2. 查看 AUTH 编号、任务对象和工具范围，点击“确认授权并执行”。
3. 展开模型请求与工具事件；真实模型选择工具，后端执行，结果回传模型，最多 8 轮 / 20 次工具调用。
4. 最终结果必须有工具证据引用；缺少角色要求的任一工具则不记成功。
5. 人工选择处置并输入理由，仅记录本地模拟决定。模型没有处置接口。
6. 选择验证报告或日志排查 Agent，以刚才的执行为输入，再创建和审批任务。
7. SIM-CASE-003 的交易数据缺失，必须转人工；可验证取消、错误或超时后的历史记录。

## 能力边界

- 原 14 页入口仍可从页头访问，是固定模拟快照，不与运行版自动同步。当前真正接通的是新运行工作台、任务、工具与证据链；不是 14 页全部后端化。
- 业务表为预置只读模拟样本，运行状态存 SQLite。暂不接真实交易、账户、生产系统。
- 这不是完整实验平台：单次检查不能证明准确率、样本覆盖、基线回退或四门禁通过，不能生成生产发布资格。
- 人工处置只针对本地任务留痕；不执行真实拦截、解除、注册或在线写入。
- 全部授权绑定当前任务和角色，不支持运行中修改提示词或跨任务继承审批。
- 仅单人本机访问；无多租户、账户登录、高可用或生产级权限体系。
- API 总时限 180 秒，单次请求 60 秒，单次输出上限 1500 token。用量记录来自供应商 usage，缺失记未知；这些限制不等于固定金额预算。
- API 兼容性需实际验证（工具调用、max_tokens 等）；模型不支持或返回不合法时明确失败，不自动换模型或假装成功。
- 执行日志记录输入、结果和调用元数据，不记录或展示模型内部思维链。

## 验证

```sh
npm test
```

自动化测试使用明确的 protocol-test-double 模型替身，覆盖协议闭环、未授权、越权、错误、超时、取消、重启、持久化与 HTTP 边界。替身测试不证明模型实际可用。

真实联调验收：配置实际供应商，执行一次调查任务，检查状态、工具结果、最终引用以及 usage；再运行验证和日志角色。没有真实 API 回执前，不宣称三个 Agent 真实联调通过。

接口实现参考：[OpenAI 官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)。供应商必须支持该 Chat Completions 工具循环，不能仅支持纯文本对话。
