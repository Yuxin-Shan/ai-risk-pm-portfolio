# 验收标准

> 本文档给出每条验收标准的 Given / When / Then 与量化阈值。评审时按条核对:能演示、能判定。

## 一、在线链(8 条)

### AC-01 策略规则可查、可切换版本

| 项 | 内容 |
|---|---|
| Given | 已有一套生效中的策略规则与阈值 |
| When | 打开策略引擎配置,查看规则详情并切换到历史版本 |
| Then | 能看到规则内容、阈值、生效范围;版本切换后有明确的状态标识 |
| 判定 | 规则详情字段完整(名称、条件、阈值、生效范围、版本号、生效时间),切换动作有反馈 |
| 关联指标 | M-01 |

### AC-02 分流边界与临时管控可见

| 项 | 内容 |
|---|---|
| Given | 有一批命中案件 |
| When | 查看分流结果 |
| Then | 能看到:命中瞬间的临时管控(挂起 / 空处罚)已执行;案件被判为"确定性结案"或"转 Agent",各自依据的阈值与白名单可见 |
| 判定 | 每笔案件可见判定路径与所依据的阈值;无法归因时的默认走向是转 Agent 并告警,不是放行 |
| 关联指标 | M-02 |

### AC-03 实时监控可看可下钻

| 项 | 内容 |
|---|---|
| Given | 在线链在持续产生日志 |
| When | 打开实时监控看板 |
| Then | 看到命中率、转 Agent 率、裁决时延 P95、拦截率、转人工率、工具调用失败率、待人工介入积压时长;点击任一指标可下钻到案件样本列表,可按结果与耗时筛选 |
| 判定 | 7 个指标数值与日志口径一致;下钻拿到具体案件列表;**下钻不产出归因结论**(归因在排查链) |
| 关联指标 | M-01 ~ M-06、M-17 |

### AC-04 抽检可推翻裁决并落负样本

| 项 | 内容 |
|---|---|
| Given | 有一笔 Agent 判定为拦截的案件 |
| When | 在抽检入口打开该案,查看证据链后点击推翻 |
| Then | 裁决被推翻,管控解除,推翻记录留存,该案样本落入工作台的数据集管理(负样本集) |
| 判定 | 推翻后案件状态正确变更;证据链可逐步展开;推翻操作被记入抽检记录;样本在数据集管理中可查 |
| 关联指标 | M-07 |

### AC-05 对话可受理需求并给出执行计划

| 项 | 内容 |
|---|---|
| Given | 工作台已配置若干 Agent 与已授权工具 |
| When | 用户在对话里输入"把上周那批转账案件重跑一遍" |
| Then | 工作台输出可读的执行计划(分几步、每步做什么、预计耗时),经用户确认后开始执行,进度回显在对话流里 |
| 判定 | 计划步骤与**最新确认版本**一致(中途中断改参数后,以更新后的计划为基准);不存在的工具或数据集不出现在计划中;需求歧义时反问而非擅自执行 |
| 关联指标 | M-11、M-13 |

### AC-06 执行过程可打断、可追加参数

| 项 | 内容 |
|---|---|
| Given | 一个多步任务正在执行中 |
| When | 用户在对话里要求暂停或追加参数 |
| Then | 任务按指令变更:静默暂停,或带新参数重新执行受影响的部分;对话流里出现更新后的执行计划 |
| 判定 | 中断动作有反馈;更新后的计划可见;已产生的部分结果未被丢弃,并标注"基于旧参数";新增参数确实体现在后续执行中 |
| 关联指标 | — |

### AC-12 待人工介入队列可处置

| 项 | 内容 |
|---|---|
| Given | 有一笔案件因必需工具失败或取证超时,Agent 未能得出裁决 |
| When | 值守人员打开实时监控内的待人工介入队列 |
| Then | 看到该案及其已获取的证据链;确认裁决或解除管控后,案件结案并移出队列 |
| 判定 | 队列按类型与积压时长排序;可选工具失败的案件**不在队列内**(Agent 已降级继续);必需工具失败的案件在队列内;积压超阈值时看板告警 |
| 关联指标 | M-05、M-17 |

## 二、离线链(6 条)

### AC-07 实验能跑出对比结果

| 项 | 内容 |
|---|---|
| Given | 有一个待验证的 Agent 版本与一个对照基线 |
| When | 建立实验并执行 |
| Then | 输出两组的评测结果对比,含样本量、覆盖率、门禁四项的达成情况 |
| 判定 | 结果中样本量、时间窗、口径均可见;样本量或覆盖率不足时明确标注"不构成验证结论" |
| 关联指标 | M-08、M-09 |

### AC-08 Agent 配置可改可存版本

| 项 | 内容 |
|---|---|
| Given | 已有一个 Agent 配置 |
| When | 修改提示词或可调用工具范围并保存 |
| Then | 生成新版本,旧版本可查,改动有记录 |
| 判定 | 版本可追溯;权限边界字段存在且可查看 |
| 关联指标 | — |

### AC-09 工具可注册、可授权、可查调用记录

| 项 | 内容 |
|---|---|
| Given | 有一个新的取证工具接口 |
| When | 在工具台注册、定义参数,生成授权待审批包,并在在线侧完成确认 |
| Then | 确认后该工具对指定在线 Agent 生效;该 Agent 在后续取证中可调用它,调用记录可按案件查询 |
| 判定 | 未完成确认前该 Agent 无法调用;未授权的 Agent 无法调用;调用记录含时间、入参摘要、结果状态 |
| 关联指标 | M-06 |

### AC-10 离线任务可批量执行、可重试

| 项 | 内容 |
|---|---|
| Given | 有一批待调查的历史案件 |
| When | 建任务并入队执行,其中一条人为制造失败 |
| Then | 其余任务正常完成;失败任务可重试并成功 |
| 判定 | 任务状态流转清晰(排队 / 执行中 / 成功 / 失败 / 重试中);失败原因可见 |
| 关联指标 | M-11、M-12、M-13 |

### AC-11 证据链视图可独立使用

| 项 | 内容 |
|---|---|
| Given | 有一笔已完成或多步进行中的案件 |
| When | 单独打开证据链视图(不经抽检入口) |
| Then | 逐步展示每步的工具、时间、输入摘要、结果状态、证据缺失标识;可从证据回溯到案件与 Agent 版本 |
| 判定 | 步骤顺序与日志一致;缺失步骤有明确标识;可筛选与深看单步 |
| 关联指标 | M-16 |

### AC-13 验证报告可生成待注册包,并经人在线侧注册生效

| 项 | 内容 |
|---|---|
| Given | 有一个达到门禁四项的 Agent(样本覆盖 ≥80%、证据链完整率 ≥90%、未授权调用 =0、相对基线退化 ≤5%) |
| When | 打开验证报告,确认门禁达成,生成待注册包;凭包编号切换到在线侧**模型服务页**,调取包内容并确认注册 |
| Then | 该 Agent 出现在在线侧模型服务列表;实时监控可见全局相关指标的变化 |
| 判定 | 门禁任一项未过时,生成待注册包的入口不可用,只能打回并标注未过项;四项门禁分别对应 M-09(样本覆盖)、M-18(证据链完整率)、M-19(未授权调用)、M-20(相对基线退化);待注册包内容与实验结论一致;注册动作发生在在线侧,工作台侧无写在线侧记录;**AC-13 是离线转线上的唯一路径** |
| 关联指标 | M-08、M-09、M-10、M-18、M-19、M-20 |

## 三、排查链(1 条)

### AC-14 日志可回放、可定位异常

| 项 | 内容 |
|---|---|
| Given | 在线看板显示某时段裁决分布异常,日志在留存期内 |
| When | 在工作台发起回放该时段 |
| Then | 重建该时段每笔案件的可审计决策轨迹:命中什么、调了什么工具、拿到什么证据、得出什么;可按结果或耗时筛选并逐案展开 |
| 判定 | 回放的步骤与当时日志一致,**不出现日志中没有的推理步骤**;不呈现模型内部推理;日志缺失或超期时明确告知 |
| 关联指标 | M-14、M-15、M-16 |

### AC-16 在线 Agent 可完成调查并正确收敛案件状态(主线)

| 项 | 内容 |
|---|---|
| Given | 有一笔已由分流层判定为高疑难、已执行临时管控、并转给在线 Agent 的案件 |
| When | 在线 Agent 从异步队列接单,调用已授权工具完成多步取证 |
| Then | 输出裁决(拦截 / 放行)+ 证据链 + 置信度,回填案件,写日志;案件状态从"调查中"转为"已裁决";临时管控按四终态收敛 |
| 判定 | ① 成功分支:证据链步骤与工具调用记录一致;拦截 / 放行能在实时监控 M-04 计数上对应;放行→解除挂起,拦截→转正式拦截。② 失败分支:必需工具失败 / 取证超时 / 证据不足时**不输出强行裁决**,进入 AC-12 队列。③ 演示入口:实时监控的案件详情内可查看在线调查轨迹 |
| 关联指标 | M-03、M-04、M-05、M-06 |

## 四、端到端(1 条)

### AC-15 三条线能接上(整体验收)

| 项 | 内容 |
|---|---|
| Given | Demo 完整可运行 |
| When | 依次演示在线链、离线链、排查链,并在三处衔接各演示一次:①验证报告 → 待注册包 → 人在线侧注册 → 实时监控可见;②工具台注册 → 人确认 → 在线 Agent 取证可调用;③在线日志 → 工作台回放 |
| Then | 三处衔接都成立;离线链产出的 Agent 能在在线侧生效并能被监控;在线侧产生的日志能被排查链回放 |
| 判定 | 三处衔接各至少演示一次;每次衔接的数字能在指标口径表里找到对应条目;注册与授权的生效动作均由人在在线侧执行,工作台未写入在线侧 |
| 关联指标 | 全部 |

## 五、明确不验收的

| 不验收 | 原因 |
|---|---|
| 准确率 / 召回率达标 | 模拟数据 |
| 性能 / 并发能力 | 原型不承载性能验证 |
| 权限体系完整性 | 不做 |
| 数据一致性(真实场景) | 模拟数据 |
| 界面视觉规范 | 原型阶段不考虑 |
