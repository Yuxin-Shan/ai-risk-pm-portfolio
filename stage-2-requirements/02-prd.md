## 一、背景与目标

### 1.1 这是什么

一套在线风控系统的**异步调查层**。规则引擎在实时链上做全量判定,把其中高疑难、低置信的案件送出来,由在线 Agent 动态多步取证后裁决拦截或放行。策略 / 模型团队不逐案介入,通过看板监控和人工抽检保持对质量的掌控。

配套一个 **AI 工作台**,主界面是对话窗口。运营者用自然语言下达需求,工作台调度 Agent 与工具完成:配置 Agent、注册工具、跑评测、出验证报告、排查线上异常。达到门禁的 Agent 会生成**待审批注册包**,由策略 / 模型团队在在线侧模型服务页确认注册后,才进入实时链。

**实时链与工作台之间没有运行时接口交互。** 实时链只写日志;工作台只读日志。唯一的发布路径是"工作台生成待审批对象 → 人在线侧执行"。

### 1.2 为什么做

规则引擎能回答"是否命中",回答不了"为什么命中、还该查什么"。疑难案件的深度取证要靠人逐笔拼装,而线上流量是百万级/分钟,人力扩不动。真正卡住的不是算法,是管理成本。

另两层动机:Agent 想上线,不能凭感觉,需要一个能验证它的地方;线上出了问题,需要一个能回放决策轨迹的地方。这两件事都在工作台。

### 1.3 本 Demo 的成功标准

**成功 = 三条线能讲通,且每个数字能解释来源。**

不是业务 KPI,不是准确率达标。是一个能演示的产品流程,让看的人相信:设计者知道这套东西怎么运转、边界在哪、哪里会出错。

## 二、用户与场景

### 2.1 用户

**策略 / 模型团队,唯一核心用户。** 三项诉求:看实时异常、做分析定位问题、优化策略与模型。

不设一线调查员。抽检与待人工介入队列的处置,由策略 / 模型团队的值守角色承担。

### 2.2 核心场景

**场景 A:疑难案件转 Agent 后自动裁决(线上)**

- Given 规则引擎命中一笔交易,置信度低于阈值,确定性层已执行临时管控(挂起 / 空处罚)
- When 案件进入异步队列,在线 Agent 执行多步取证
- Then Agent 输出裁决(拦截 / 放行)与证据链,回填到案件,写日志;判错的由后续抽检或申诉解除管控

**场景 B:策略团队通过看板发现异常(线上)**

- Given 某类裁决的拦截率连续两个统计周期异常上升
- When 团队打开实时监控下钻
- Then 看到受影响案件样本列表,可按结果与耗时筛选
- 归因(是规则、工具还是 Agent 的问题)在排查链完成,不在看板

**场景 C:人工抽检推翻 Agent 裁决(线上)**

- Given 抽检命中一笔 Agent 判定拦截的案件
- When 策略 / 模型团队成员查看证据链后发现证据不足
- Then 可推翻裁决、解除管控,该样本落入工作台的数据集管理作为负样本

**场景 D:用对话验证一个新 Agent 能否上线(离线)**

- Given 需要判断一个调查 Agent 是否适合上线
- When 运营者在对话里说"验证一下新版提示词",工作台建实验、取数据集、跑任务
- Then 出具验证报告;达到门禁的生成待注册包,由人在线侧确认注册;未达门禁的打回修改

**场景 E:用对话跑一批历史案件重查(离线)**

- Given 有一批历史案件需要重新调查
- When 运营者说"把上周那批转账案件重跑一遍"
- Then 批量产出结论与证据链,失败任务可重试

**场景 F:工具注册与授权(离线)**

- Given 在线 Agent 需要一个新取证工具
- When 在工具台注册、定义参数,并生成授权待审批包
- Then 经人在线侧确认后,该工具对该 Agent 生效,调用记录可查

**场景 G:线上异常排查(离线 · 读日志)**

- Given 在线看板显示某时段裁决异常
- When 运营者说"回放昨天 14:00-14:15 那段转账案件"
- Then 工作台读日志重建可审计决策轨迹,逐案看证据链,定位是规则、工具还是 Agent 判断问题

**场景 H:必需工具失败转人工(线上)**

- Given 某笔案件调查中,必需工具不可用或取证超时
- When 案件无法得出可支撑裁决的证据链
- Then 案件进入待人工介入队列,由值守人员在实时监控内确认后结案

### 3.2 不做

| 不做 | 原因 |
|---|---|
| 同步热路径上的 LLM 推理 | LLM 非确定性,不进实时判定链 |
| 实时链与工作台的运行时接口调用 | 只经日志解耦 |
| 工作台直接写入或改动在线侧配置 | 只能生成待审批对象,生效由人在线侧执行 |
| 多租户与权限体系 | 原型不承载组织复杂度 |
| 真实数据接入 | 全程模拟数据 |
| 数据治理与血缘的完整实现 | 架构图中画依赖,不做实现 |
| 模型训练过程 | 只做模型服务管理 |
| 移动端适配 | 桌面演示 |

### 3.3 Demo 范围与真实系统的分界

Demo 里每个页面都有数据、有交互反馈、有异常态。但**数据是模拟的、链路是简化的、规模是缩小的**。真实系统要处理的部分(高可用、性能、灾备、审计合规)在本 Demo 中只以界面元素存在,不做实现。

### 4.2 关键功能说明

#### FR-02 案件分流与转 Agent(含临时管控)

| 项 | 内容 |
|---|---|
| 输入 | 规则引擎的实时判定结果:命中项、置信度、命中特征 |
| 处理 | ① 命中瞬间由确定性层执行临时管控(挂起 / 空处罚);② 确定性规则(阈值 + 白名单)判定是否属于高疑难 / 低置信 |
| 输出 | 两路:直接结案并解除管控 / 生成事件快照转在线 Agent |
| 异常态 | 分流规则未命中任何条件时**默认转 Agent 并告警**,不默认放行 |

**分流是确定性动作,不由 Agent 决定。** 这一条是架构成立的前提。

**为什么默认转 Agent 而非放行:** 分流漏判意味着"该查的没查"。默认转 Agent 的代价是多一次异步调查,默认放行的代价是漏过风险。在无法归因时选择更保守的一侧。

#### FR-06 待人工介入队列处置

| 项 | 内容 |
|---|---|
| 输入 | 在线 Agent 未能得出裁决的案件(必需工具失败 / 取证超时 / 证据不足) |
| 处理 | 案件进入实时监控内的待人工介入队列,按类型与积压时长排序 |
| 输出 | 值守人员查看已有证据链后确认裁决或解除管控,案件结案 |
| 异常态 | 队列积压超过阈值时在看板告警 |

**工具失败的分级处理:** 可选工具失败 → Agent 跳过该步,证据链标注缺失,继续推理;必需工具失败 → 无法支撑裁决,转待人工介入。

#### FR-08 执行过程的确认与打断

| 项 | 内容 |
|---|---|
| 输入 | 用户在任务执行中的追加、暂停、取消指令 |
| 处理 | 需确认的动作挂待确认卡片;已入队的任务支持暂停与参数追加 |
| 输出 | 变更后的执行状态与**新的执行计划** |
| 异常态 | 已产生的部分结果不丢弃,标注为"基于旧参数" |

#### FR-11 工具注册与授权配置

| 项 | 内容 |
|---|---|
| 输入 | 工具的接口定义、参数、数据源、**必需性(必需 / 可选)** |
| 处理 | 注册到工具台,配置可调用的 Agent 范围,生成授权待审批包 |
| 输出 | 待审批包;经人在线侧确认后,工具对该 Agent 生效 |
| 异常态 | 未完成确认前,Agent 无法调用该工具;调用失败时按分级处理降级 |

**必需性字段决定失败分支:** 可选工具失败 → 跳过并标注;必需工具失败 → 转待人工介入。

#### FR-15 验证报告与待注册包

| 项 | 内容 |
|---|---|
| 输入 | 实验的评测结果与证据链抽查记录 |
| 处理 | 汇总成验证报告,按门禁规则给出结论 |
| 输出 | 达到门禁 → 生成**待注册包**;未达门禁 → 打回修改 |
| 异常态 | 评测未达门禁时不允许生成待注册包 |

**门禁是 Demo 内的模拟判定,含四项:**

| 项 | 模拟门禁 | 对应指标 |
|---|---|---|
| 样本覆盖 | 评测样本覆盖数据集 ≥ 80% | M-09 |
| 证据链完整率 | 抽查样本中证据链完整 ≥ 90% | M-18 |
| 未授权调用 | = 0 | M-19 |
| 相对基线退化 | 关键指标较对照基线退化不超过 5% | M-20 |

"关键指标"取 M-04(拦截率)与 M-07(抽检推翻率),在实验集上做模拟基线对比。四项全过 → 生成待注册包;任一项不过 → 打回,报告标注未过项。真实阈值待业务确认。

#### FR-16 在线侧确认注册

| 项 | 内容 |
|---|---|
| 输入 | 工作台生成的待注册包 / 工具授权包(带包编号) |
| 处理 | 策略 / 模型团队在**在线侧模型服务页**凭包编号调取包内容并确认 |
| 输出 | 该 Agent 出现在在线侧模型服务列表;实时监控可见其相关指标(全局指标变化);工具授权包则使工具对该 Agent 生效 |
| 异常态 | 待审批包与实际配置不一致时拒绝;可拒绝并退回工作台 |

**这是离线转线上的唯一路径,且生效动作由人执行。** 工作台不直接写在线侧。跨边界传递在 Demo 中表现为**人工导出 / 导入**:工作台输出带编号的包,人在在线侧凭编号调取 —— 不走接口。

#### FR-18 在线 Agent 异步取证、裁决与回填

| 项 | 内容 |
|---|---|
| 输入 | 规则引擎生成的事件快照(不可变):命中项、命中特征、主体信息 |
| 处理 | 在线 Agent 从异步队列接单 → 调用已授权工具完成多步取证 → 汇总为证据链 → 输出裁决(拦截 / 放行)与置信度 |
| 输出 | 裁决 + 证据链回填到案件;案件状态从"调查中"转为"已裁决";写日志 |
| 异常态 | 必需工具失败 / 取证超时 / 证据不足 → **不输出强行裁决**,转 FR-06 待人工介入队列 |

**支撑该过程的演示入口:** 实时监控的案件详情内查看在线调查轨迹(取证步骤、工具、证据链、裁决)。

**临时管控的收敛(四个终态):**

| 情形 | 临时管控怎么变 |
|---|---|
| 分流层确定性结案 | 解除管控 |
| Agent 裁决放行 | 解除挂起 |
| Agent 裁决拦截 | 转为正式拦截,保持管控直至推翻或申诉 |
| 人工处置后 | 按其结论解除或转为正式拦截 |

#### FR-17 日志回放与异常定位

| 项 | 内容 |
|---|---|
| 输入 | 时间段、案件类型等查询条件(由对话或表单给出) |
| 处理 | 读在线日志,重建该时段每笔案件的**可审计决策轨迹**:命中什么、调了什么工具、拿到什么证据、得出什么 |
| 输出 | 可逐案展开的回放视图,支持按结果 / 耗时筛选 |
| 异常态 | 日志缺失或留存期外时明确告知,不伪造推理过程 |

**方向是单向的:工作台读日志,不写日志。** 回放只展示日志中实际存在的内容,不还原模型的内部推理。

### 4.3 Agent 示例定义

#### 在线 Agent:反欺诈调查 Agent

| 项 | 内容 |
|---|---|
| 目标 | 解决"疑难案件定性"这类工作 |
| 触发条件 | 规则引擎判定为高疑难 / 低置信,且案件进入异步队列 |
| 任务契约 | 输入:不可变事件快照;输出:裁决(拦截 / 放行)+ 证据链 + 置信度 |
| 可调用工具 | 主体信息查询、历史交易比对、名单匹配、关联关系查询 |
| 裁决与回滚规则 | 裁决直接生效;抽检可推翻;推翻后解除管控并记录;申诉通道作为制度设计在原型中不做 |
| 失败模式 | 必需工具失败、取证超时、证据不足以支撑任一裁决 → 进入待人工介入队列(实时监控内),由值守确认结案 |
| 边界 | 不接触实时链路的判定逻辑,不改动在线策略,不自动更新名单 |

**在线 Agent 敢直接裁决的三个前提:**
1. 只处理规则引擎筛出的硬骨头,案件本身处于低置信区间
2. 命中瞬间的临时管控(挂起 / 空处罚)已由确定性层执行,判错不漏放
3. 裁决可回滚:拦截后可由抽检推翻并解除管控(申诉通道是真实系统的制度设计,原型不做)

#### 工作台 Agent:运营助手 Agent

| 项 | 内容 |
|---|---|
| 目标 | 理解运营者的自然语言需求,调度工具与子任务完成 |
| 输入 | 用户对话;可读的在线日志 |
| 可调用能力 | 实验管理、Agent 配置、工具台、任务队列、证据链、验证报告、日志回放 |
| 权限边界 | 不直接写在线侧;注册、授权、策略变更只能生成待审批对象 |
| 失败模式 | 需求歧义 → 反问;工具不可用 → 告知并给替代路径 |

## 五、成功标准

### 5.1 演示成功的判定

| 项 | 判定 |
|---|---|
| 线上线可走通 | 从实时命中到**裁决回填、管控收敛**,一条线点得下去(见 AC-16) |
| 离线线可走通 | 从一句话需求到出验证报告、生成待注册包,一条线点得下去 |
| 排查线可走通 | 从看板异常到日志回放定位原因,一条线点得下去 |
| 三条线能接上 | 三处衔接各演示一次(见 AC-15) |
| 数字可解释 | 演示中每个数字能说出怎么算出来的 |
| 异常态可见 | 至少演示一次失败 / 待人工介入的分支 |
| 边界能说清 | 被问到"为什么不用 Agent 做实时""为什么走日志不走接口""注册为什么不由工作台直接执行"时,答案已在文档里 |

### 5.2 明确不追求的

| 不追求 | 原因 |
|---|---|
| 准确率 / 召回率达标 | 模拟数据,无实测意义 |
| 性能指标 | 原型不承载性能验证 |
| 完整的运营闭环 | 演示聚焦调查、裁决、验证、排查这几段 |
