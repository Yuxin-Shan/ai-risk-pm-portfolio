## 一、Agent 分两类

一个 Agent 的目标是解决某类工作。按工作性质分两类:

| | 在线 Agent | 工作台 Agent |
|---|---|---|
| 干什么 | 实时链上识别风险、取证、裁决 | 接受自然语言指令,调度工具与子 Agent,完成运营任务 |
| 例子 | 反欺诈调查 Agent | 运营助手 Agent |
| 上线后成为 | 模型服务 / 特征,注册到在线风控侧 | 留在工作台 |
| 用哪套看板 | 在线侧实时监控(只读日志指标) | 工作台自己的任务与实验视图 |
| 与另一侧的关系 | 只写日志,不调用工作台 | 只读日志;能生成待审批对象,不能直接写在线侧 |

**两类不冲突。** 在线 Agent 干完活留日志;工作台的助手 Agent 事后读日志干活。它们通过日志这个介质协作,而不是通过接口互相调用。

## 二、界面总账与分档

### 2.1 对话窗口(主界面,单列)

| 名称 | 干什么 | 档位 |
|---|---|---|
| 对话窗口 | 工作台主界面。自然语言下达风控运营需求,调度能力完成 | **A** |

它是工作台的打开即见界面,不属于下面的 13 个编号界面,单独列出以避免与编号界面混淆。

### 2.2 在线风控侧(实时链)

| # | 界面 | 干什么 | 档位 |
|---|---|---|---|
| 1 | 策略引擎配置 | 规则 / 阈值 / 名单挂载,版本化管理 | **A** |
| 2 | 名单管理 | 黑白名单增删改查 + 生效范围 | B |
| 3 | 特征发布 | 特征定义、上线、版本切换 | B |
| 4 | 模型服务 | 模型注册、版本、上下线;**在线发布确认页**(接收工作台的待注册包与工具授权包,由人确认生效) | **A** |
| 5 | 实时监控 | 命中率、异常率、裁决分布、告警;抽检入口;待人工介入队列 | **A** |

**实时链的边界(重要):** 命中 → 分流 → 在线 Agent 取证 → 裁决。全程只做两件事:**写日志、出指标**。它不向工作台发起任何调用,不等工作台返回。在线侧的性能与可用性不依赖离线侧。

### 2.3 离线侧 · AI 工作台的能力板块

| # | 板块 | 干什么 | 档位 |
|---|---|---|---|
| 6 | 实验管理 | 新建实验、配对照组、跑评测、结果对比 | **A** |
| 7 | Agent 配置 | 提示词、可调用工具、权限、边界、版本 | **A** |
| 8 | 工具台(MCP / Skill / CLI) | 工具注册、授权、调试、调用记录 | **A** |
| 9 | 任务队列 | 离线调查任务:排队、执行、失败重试 | **A** |
| 10 | 证据链视图 | 单案取证过程回放与检查(共享组件) | **A** |
| 11 | 验证报告 | 验证结论 → 生成待注册对象 | **A** |
| 12 | 数据集管理 | 评测集、样本标注、版本;承接抽检推翻的负样本(离线导入,非接口直写) | B |
| 13 | 日志回放 | 读取在线日志,回放一段实时链的完整经过,用于异常排查 | **A** |

### 2.4 分档合计

| 档 | 数量 | 处理方式 | 判定标准 |
|---|---|---|---|
| **A** | 11 | 真交互,能走完完整故事 | 主演示线或核心流上缺一不可 |
| **B** | 3 | 有界面、有数据、能展示,支持增删改查或单个动作,不做多步引导流 | 支撑主线的背景能力 |
| **C** | 0 | — | 无 |

**A 档 11 个:** 对话窗口、策略引擎配置、实时监控、模型服务、实验管理、Agent 配置、工具台、任务队列、证据链视图、验证报告、日志回放。

**A 档编号界面 10 个** + 对话窗口 1 个 = 11。

**为什么模型服务进 A 档:** 它是全 Demo 唯一发布路径的终点 —— 工作台的待注册包、工具授权包都在这里由人确认生效。按 A 档标准(核心流上缺一不可),它必须可点通,不能只做展示。

## 三、主界面:对话窗口

工作台打开即是对话界面。用户用自然语言提需求,工作台理解后调度能力完成,过程与结果都在对话流里呈现。

```
用户:「把上周那批转账案件重跑一遍,顺便比一下新改的提示词」

工作台(展示执行计划):
  1. 建实验:新版 prompt vs 现网版本
  2. 取数据集:上周转账案件 3,812 笔
  3. 建两组任务入队
  4. 完成后出对比结果

[执行中 2/4]  ████████░░░░ 预计 12 分钟

用户:「先停一下,把可疑样本的手法特征也带上」

工作台:「收到,已加进任务参数,重跑第 2 组。」
```

**对话不是聊天框,是操作台。** 每一句需求都可能触发:调 Agent 配置、建实验、建任务、查证据链、出报告。

### 3.1 对话如何与已有 Agent / 工具交互

| 问题 | 处理方式 |
|---|---|
| **怎么知道该调哪个工具?** | 助手 Agent 持有工具台的**工具清单**(含名称、描述、参数 schema),按语义匹配候选,匹配不唯一时向用户确认 |
| **执行中途要用户确认怎么办?** | 需要确认的动作(如批量重跑、发起注册)在对话流里挂**待确认卡片**,用户点或直接回话都算答复 |
| **能不能在对话里看证据链?** | 能。证据链视图作为**可嵌入组件**出现在对话流中,展开即看逐步取证;也可跳转到独立页面深看 |
| **对话产出的东西怎么落成正式对象?** | 每次执行都生成对象:实验、任务、证据链、报告、待审批包。对话只是入口,对象才是载体 |

### 3.2 权限与边界

| 能做 | 不能做 |
|---|---|
| 读在线日志 | 写日志 |
| 生成实验、任务、证据链、报告 | 改动实时链的任何配置 |
| 生成**待审批包**(注册包 / 工具授权包) | 直接把模型服务 / 特征 / 策略写入在线侧 |

**工作台的所有产出都是"待审批对象",生效动作由人在在线侧界面完成。** 这是工作台与在线侧之间唯一允许的发布路径,详见《PRD》FR-15 / FR-16。

**跨边界对象怎么传:** Demo 里用**人工导出 / 导入**表现 —— 工作台输出带编号的待审批包,人在在线侧界面凭包编号调取并确认。不走接口,也不暗示工作台直写在线侧。

## 四、三条演示线

### 线 1:线上实时链(在线风控侧)

```
实时命中(策略引擎配置出示阈值)
        ↓
命中瞬间:确定性层执行临时管控(挂起 / 空处罚)  ← 先兜底,再调查
        ↓
规则引擎分流:能确定性判 → 结案并解除管控
              高疑难/低置信 → 转在线 Agent
        ↓
在线 Agent 取证(调用已授权工具)
        ↓
    ┌───┴────┐
证据充分         必需工具失败 / 取证超时 / 证据不足
    ↓                  ↓
输出裁决 + 证据链    进入待人工介入队列(实时监控内)
回填案件,写日志          ↓
    ↓              策略 / 模型团队值守确认 → 结案
临时管控收敛
(拦截→正式拦截 / 放行→解除挂起)
    ↓
实时监控(实时监控内看异常态与积压)
    ↓
人工抽检:翻样本、看证据链、推翻或确认
```

**这条线全程不碰工作台。**

### 线 2:离线运营链(AI 工作台 · 对话式)

```
用户对工作台说:「验证新版提示词的效果」
        ↓
助手 Agent 拆解:建实验 + 取数据集 + 建任务
        ↓
用户在对话里看到执行计划,确认
        ↓
任务执行,证据链可展开
        ↓
出验证报告
        ↓
    ┌───┴───┐
达到门禁        未达门禁
    ↓              ↓
生成待注册包     对话里说"哪里不行"
    ↓              ↓
凭包编号在在线侧      改 Agent 配置 → 重跑
模型服务页确认生效
    ↓
进入在线侧,实时监控可见
```

### 线 3:异常排查(工作台 · 读日志)

```
在线看板发现指标异常
        ↓
进工作台,说:「回放 14:00-14:15 那段」
        ↓
工作台读日志,重建可审计决策轨迹
        ↓
逐案看证据链 → 定位问题
        ↓
    ┌───┴───┐
策略问题         Agent 问题
    ↓              ↓
进策略引擎配置      进 Agent 配置改
```

## 五、不做清单

| 不做 | 原因 |
|---|---|
| 同步热路径上的 LLM 推理 | LLM 非确定性,不进实时判定链(在线 Agent 走异步队列,不受此限) |
| 实时链与工作台的运行时接口调用 | 只经日志解耦,避免离线侧拖累线上 |
| 工作台直接写入或改动在线侧配置 | 只能生成待审批对象,生效由人在线侧执行 |
| 多租户与权限体系 | 原型不承载组织复杂度 |
| 真实数据接入 | 全程模拟数据 |
| 数据治理与血缘的完整实现 | 架构图中画依赖,不做实现 |
| 模型训练过程 | 只做模型服务管理 |
| 移动端适配 | 桌面演示 |
| 独立的"在线 Agent 管理"界面 | Agent 上线后即为模型服务 / 特征 |
| 申诉通道 | 真实系统需制度设计(受理、复核、时限),原型不做 |
