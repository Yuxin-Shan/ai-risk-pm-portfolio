## 三条最关键结论

### 1. D1 表述必须改(三家一致)
- 行业里"线上防控"=**决策在业务动作完成前返回**(毫秒~百毫秒);"准实时"通常=**秒级**;**分钟级 = 近线(Near-line)/异步处置**,不是线上防控。
- 分钟级结论返回时交易多已完成,只能做"事后拦截+止付/冻结/客诉"。
- **建议改称:「近线异步处置 / 第二道防线」**,不称"线上防控"。(DSH:此措辞会被风控内行一眼看穿)
- Codex 给出可采纳的**时延分层**(按"决策能改变什么"切分,非按模型类型):
  - `<50ms/1s`:硬规则+名单+轻量模型 → **拦截型**(支付放行/拒绝、登录拦截、限额)
  - `1–10s`:流式特征+实时模型 → 会话级拦截/强验证(补设备/关系特征、延迟确认),须超时降级
  - `10s–1min`:多源聚合/图计算 → **处置型**(订单暂挂、账户临时保护)
  - `1–5min`:可冻结/撤回场景的复核、疑难初判、队列优先级
  - `小时级+`:团伙发现、案件调查、策略挖掘、名单更新、模型训练、Agent 实验
- Claude 强调:称得上"线上防控"须满足**六项工程条件**:事件驱动调度+优先级队列 / 端到端 P95≤3min+超时 fail-safe / 重试+死信队列 / 幂等 / **结果回写在线特征(闭环,否则只是一次性动作)** / 可观测。

### 2. 黑名单不可下沉(重要补充)
- 排白(业务白名单)可下沉特征层;但**制裁名单/黑名单命中属硬拦截,必须保留为最高优先级独立闸门**——下沉会有合规硬伤(DSH),且误排白会绕过后续控制(Codex/Claude)。
- 排白必须带作用域(场景/金额区间)+TTL,禁止全局"排白即放行",命中仍过兜底校验,全量留痕。

### 3. D3 措辞改"闭环边界接口"(低成本高收益)
- 准入(KYC/进件反欺诈)本就属核心风控域;申诉/举报是**监管硬要求**(GDPR 异议权、中国投诉举报机制、EU AI Act 人工监督);处置是风控的"牙齿"。
- 组织归属观察为真,但**架构图必须显式留位**,称"闭环边界接口/配套能力",不能定性为"不属于核心治理"——否则被诟病架构不完整。
- 工程上须补两个闭环:①处置指令**回执对账**(防"已判定未执行");②**申诉结果回流**(防误伤持续、特征失准);③准入复用同一引擎(防"准入放、事中杀"不一致)。

## 其余采纳要点

**D4 发布闭环(可采纳为标准流程)**
Agent 提出候选规则+证据 → 静态检查/冲突检测 → 历史回放 → 沙箱/影子实验 → **人工批准** → 小流量灰度 → 监控回滚。
- 人工确认落在"进入任何影响真实用户的实验之前";高风险规则扩量前二次确认。
- 确认内容:适用场景、规则差异、样本与指标、误伤、合规影响、权限、有效期、熔断、回滚。
- HITL 三层(DSH):**例外介入 / 变更审批 / 抽样审计**(而非逐单)。
- **禁止 Agent 直写**(Claude):①生产规则/名单写接口 ②处置指令下发 ③训练数据/标签直写 ④人审结论改写 ⑤自身权限授予。审计须存:输入证据、数据/prompt/模型版本、规则 diff、审批人与理由、实验分桶、指标、发布时间、回滚记录。

**D5 治理面补全(合并三家)**
作者六项 + 补:决策责任与审批治理、变更/发布治理、在线监控与漂移、实验治理、人工审核质量、名单生命周期、第三方依赖、系统安全与韧性、事件响应、申诉纠错、业务连续性、**应急回滚**、**成本治理(LLM 成本配额)**;监管维度:EUT AI Act GPAI、OCC 模型验证、中国算法备案/内容标识/投诉举报。
