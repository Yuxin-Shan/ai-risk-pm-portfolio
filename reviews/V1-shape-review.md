- 时间:2026-09-10
- 评审对象:双链路假设(实时识别 / 运营排查)+ 分层假设(排白→小模型→大模型→Agent 层)+ 两个交互点
- 模式:三方独立、先调研后评审(`honnold-acpx-wave.mjs`)
- 运行结果:`status=degraded`,exitCode `0`(Codex ok / DSH ok / **Claude error exitCode 5 = PERMISSION_DENIED**,但已产出完整评审正文;属"三家中一条链报错但结果有效")

## 三方结论

| Agent | 领域 | 结论 |
|---|---|---|
| Codex | 产品 | 双链路方向基本正确,但「两者构成全部风控工作」不成立;分层不应固化为串行 |
| Claude | 工程 | 双链路+分层成立;但**实时层全量上 LLM 不成立**,价值应押异步深查+名单/特征回流 |
| DSH | 趋势 | 部分成立需修正:LLM/Agent 落在异步侧与治理侧,而非实时热路径 |

## 三方共识(高度一致)

1. **双链路划分方向正确,但不能说"构成风控全部工作"** —— 遗漏:准入/KYC、认证干预、事后止损追偿、申诉、合规报送,以及数据/标签/模型风险/权限审计等横向能力(Codex)。应为「两条执行泳道 + 一个共享控制面」。
2. **「排白→小模型→大模型→Agent」串行分层假设被否** —— 生产系统通常是**规则+传统 ML(GBDT/图/时序)并行或按场景路由**;排白只是少量高置信 fast-pass,不是普遍第一层(误排白会绕过后续控制)。
3. **实时热路径不应上生成式 LLM/开放 Agent** —— p99 秒级、成本高 3–4 个数量级、可解释/合规不达标。实时=规则+小模型;LLM/Agent=异步调查+策略/特征生成+治理(三家一致)。
4. **交互点 A(实时→异步)是行业标配、成熟** —— 关键是**传不可变事件快照**(事件+特征版本+决策上下文+分数+分流标签),调查侧不得实时回查改写当时证据。
5. **交互点 B(异步→实时)方向成立、工程最险** —— 必须三类回流分治:
   - **名单回流**:可直接生效(可审计可回滚)
   - **特征回流**:经特征平台版本化注册
   - **策略/模型回流**:**禁止直写线上**,必须走 离线评估→影子→灰度→监控→回滚 门禁
6. **被低估的趋势力量**:①**Agent 原生风险**(AI 成为交易发起方/欺诈主体、合成身份)——正是作者差异化方向;②**模型风控/AI 治理产品化**(治理优先于速度,EU AI Act/OCC 把模型清单/可解释/漂移/红队/审计变成独立产品面);③多模态风险信号融合。

## 真伪价值判断(Codex)
- **真实价值**:证据自动汇集、实体关联、自然语言查数、案件摘要、规则语法生成、历史回放解释、告警优先级排序
- **伪需求**:让大模型逐笔"思考"、Agent 自主放行/拒绝、聊天框替代专业工作台、无标签闭环的自动调参、只炫根因文字却不能复现数据与版本

## 分歧与裁定
- **产品侧**(Codex)倾向分层保留演进位;**工程侧**(Claude)主张 LLM/Agent 全放异步;**DSH** 站位:**站工程侧,给产品侧留"实验位"**——实时仅保留"已命中中风险的小流量 + 低延迟 LLM 判别器 + shadow + 强兜底"作实验,不作默认分层;Agent 决策权只在异步侧且高危须人工确认。
- **Honnold 裁定**:采纳 DSH 的折中——**默认分层不含实时 LLM/Agent,但架构图保留"实验位"**。理由:既尊重工程现实,又不封死演进路径,且这正是可写进产品判断的分寸感。

## Demo 切口(三家趋同)
首选 **「实时命中 → 异步 Agent 深度调查 → 证据链 → 高危人工确认 → 审计留痕」端到端闭环**,附加简化版「异步→实时」回流(Agent 生成候选规则 → 离线评测)。理由:落在已验证价值区,又能体现作者的越权治理/执行完整率差异化,并可附一页模型卡/门禁体现治理前瞻。
