# 阶段 4 设计基线

> 版本：v0.3（交互层级与执行侧栏口径同步）  
> 日期：2026-09-20  
> 项目属性：个人作品集；所有业务情境、案件、指标和数字均为虚构模拟，不代表真实公司实践、上线或生产数据。  
> 适用范围：阶段 4 的 14 个冻结界面及共享组件；不修改阶段 1–3 的产品结论。

## 1. 设计目标

1. **先看结果，再看过程。** 首屏先回答“正在做什么、进到哪、产出了什么、需不需要人处理”。
2. **对话是操作台，不是聊天框。** 自然语言进入后必须转成计划、状态、对象和可审计动作。
3. **高密度但不拥挤。** 通过排版、对齐与渐进下钻组织信息，不靠无限卡片和重边框。
4. **状态比装饰重要。** 执行中、暂停、失败、待确认、审批中、灰度中都必须在视野内直接可见。
5. **诚实优先。** 所有演示页固定显示“个人作品 · 虚构模拟数据”；不出现“线上真实效果”“生产提升”等暗示。

## 2. 风格方向

### 2.1 共同骨架

- **审美方向：** 工业化 / 工具感，克制装饰；
- **布局：** 严格网格，桌面优先，主断点 1200px；
- **三栏：** 216–224px 导航 + 弹性主区 + 260–280px 条件式执行/上下文栏；对话样张右栏承载任务进度，无任务时只显示低调说明；
- **装饰级别：** intentional，仅用微弱层次、选中条、细分隔与状态轨道；
- **动效：** minimal-functional，只用于状态切换、展开与反馈；
- **圆角：** 6 / 10 / 14px 分层使用，不做全局“泡泡化”。

### 2.2 两个待选视觉主题

#### A. 深色监控台 — Obsidian Signal

- **气质：** 夜间值守、实时运行、精确且克制；
- **优势：** 处理中、失败、告警和 trace 状态在暗底上更集中；适合在线侧与主线 1；
- **风险：** 若边框和发光过多会像“赛博大屏”；因此不使用霓虹渐变，主区保持哑光深灰。

#### B. 浅色业务后台 — Paper Ops

- **气质：** 清爽业务工作台、易读、可讲解；
- **优势：** 长时间阅读、表格与审批材料更自然；适合离线运营链与面试投屏；
- **风险：** 容易变成普通 SaaS；用窄侧栏、强对象编号、深蓝状态轨道与局部纸张层次建立识别度。

### 2.3 安全选择与设计风险

**安全选择**

- 左侧稳定导航 + 顶部页面工具条，符合运营后台预期；
- 表格、时间线、状态标签分别承载不同信息；
- 语义色稳定，所有状态有文字，不依赖单一色彩。

**有意承担的风险**

- 新会话以任务引导和居中输入区开场，进入会话后同一输入区固定到底部；收益是首轮操作明确，代价是需要通过执行态继续证明平台能力。
- 右栏以运行中实时步骤为主视图，对象列表降为次要区块；收益是当前进展可直接扫描，代价是主内容宽度减少。
- 深色版使用清晰蓝色作主操作与运行色，不使用常见紫色 AI 渐变；绿色只表达成功，避免“可点击”和“已完成”混淆。

### 3.3 状态规则

- 成功色不能作为普通品牌装饰，避免“绿色 = 可点”与“绿色 = 已完成”混淆；
- 审批中与灰度中不得共用标签：审批中用琥珀色，灰度中用蓝灰 + 虚线边；
- 红色状态旁必须显示失败步骤、原因摘要和恢复动作；
- 每个状态标签至少包含文字；关键状态再加 Lucide 图标。

## 4. 字体与数字

**字体栈：** `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", sans-serif`。不依赖外部字体，保证离线打开与截图稳定。

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| 页面标题 | 22 / 30px | 650 | 页面与当前任务标题 |
| 区块标题 | 15 / 22px | 650 | 执行计划、任务执行 |
| 正文 | 13 / 20px | 400–500 | 对话、说明、表格正文 |
| UI 标签 | 12 / 18px | 550–650 | 导航、按钮、状态标签 |
| 辅助文字 | 11 / 16px | 500 | ID、时间、口径、提示 |
| 关键数字 | 20–28 / 1 | 650 | 进度、指标、样本量 |

- 数字使用 `font-variant-numeric: tabular-nums`；
- 对象 ID、版本、时间可使用 `ui-monospace, SFMono-Regular, Menlo, monospace`；
- 中文正文不使用极细字重；深色主题次文字对比不低于可读阈值。

## 5. 间距、栅格与尺寸

- **基础单位：** 4px；常用序列 4 / 8 / 12 / 16 / 20 / 24 / 32；
- **页面外边距：** 20–24px；
- **卡片内边距：** 紧凑 12px、标准 16px、重点 20px；
- **行高：** 表格 36–40px，导航项 36–40px，普通按钮 32–36px，核心动作 40–44px；
- **组件间距：** 紧耦合 8px，普通 12px，区块 20–24px；
- **内容最大宽度：** 桌面工作台不设居中窄栏；主区随 1200–1440px 扩展；
- **响应式：** 低于 980px 时右侧执行/上下文栏折叠为抽屉；低于 760px 左侧导航折叠，但阶段 4 验收以桌面 1200px 为主。

## 6. 核心组件清单

### 6.1 全局框架

- 产品标识 + “个人作品 / 模拟数据”固定标；
- 两组侧栏导航（在线风控 / 工作台）；
- 页面标题、当前环境/场景、帮助与用户入口；
- 不设置可见主题切换或演示状态切换条；主题由 `?theme=dark|light`、状态 fixture 由 `?state=` 控制；
- 全局 toast 与对话框层。

### 6.2 对话操作台

- 用户消息：紧凑右对齐，不做大面积彩色气泡；
- 系统回应：无头像对话泡，使用结构化卡片；
- 任务标题：无计划时显示“对话操作台”；有计划时取第一条用户消息并截断；
- 顶栏状态指示器：十个 `runState`（含 `cancelled`）由 `renderRunIndicator()` 唯一写入；卡片不重复同义状态 badge；
- 执行计划卡：待确认时展示步骤、范围、预计耗时和确认/改参数/取消；确认后折叠为历史摘要，不复制实时进度；
- 中断反馈卡：暂停状态、参数差异、从哪一步重跑；
- 旧结果标识：明确“基于旧参数”，可保留但不混入新结论；
- 证据链摘要：默认折叠，展开后展示工具、时间、输入摘要、状态；
- 输入区：同一多行文本框在新会话居中、进入会话后固定到底部；Enter 发送，Shift+Enter 换行；
- 执行侧栏：运行中实时进度主视图，按当前状态、实时步骤、最新产出、对象、能力事实排序；对象使用紧凑行并降为次要区块；
- 右栏减配：只预览最新一项产出，不显示表格、代码块、长引用、目录、多产出切换器或横向滚动；
- 能力事实：仅在右栏底部显示 `运营助手 Agent · v3.2 · 3 工具可用`，不在左栏或其他卡片重复；
- 完整查看态：`workspaceMode: conversation | outputViewer`；主区使用手写静态安全 HTML，Escape 退出并归还焦点。

### 6.3 监控与运营

- 指标摘要、趋势图、状态分布、筛选条、数据表；
- 案件详情头、临时管控状态、Agent 调查时间线；
- 待人工介入队列、失败原因、处置操作；
- 审批包、门禁项、灰度状态与回滚入口；
- 空态、加载态、无结果态、权限不足、网络失败。

## 7. 图标规范

- 使用 Lucide Static，默认 16px，重点动作 18px，空态 24–32px；
- 默认线宽 1.75–2px；相同区域不混用填充图标；
- 图标不单独承担含义，按钮与状态都有文字；
- 样张使用的 path 均从 jsDelivr `lucide-static` 实际拉取；
- 禁止 emoji 充当正式状态图标。

## 8. 动效与交互反馈

- hover / focus：100–150ms；展开与抽屉：180–240ms；
- 使用 `ease-out` 进入、`ease-in` 离开；
- 进度变化可平滑过渡，但不得伪造持续前进；
- 点击暂停后立即更新按钮、状态文字、进度色与时间；
- 重要动作先就地反馈，再使用 toast；
- 所有键盘可操作元素必须有统一、可见且不被裁切的 `:focus-visible` 焦点环；不得用 `outline: 0` 移除焦点而不提供替代；
- 加载状态必须同时显示当前动作和文字说明；旋转指示最多播放一次，不得以无限旋转替代真实状态；
- 尊重 `prefers-reduced-motion`，关闭非必要动画。

## 9. 文案与诚实红线

- 演示页固定可见：`个人作品 · 虚构模拟数据`；
- 数字表/指标区域再次标：`模拟数据`；
- 文件头注明项目属性与数据性质；
- 禁止：`线上提升`、`生产验证`、`真实命中`、`已在某公司上线` 等无依据表述；
- 推荐：`演示口径`、`模拟结果`、`示例案件`、`待业务确认`；
- Agent 输出写“基于已记录证据生成裁决建议/演示结果”，不写“还原完整思考过程”。
- 业务规则仍为：工作台不直接修改在线配置，注册/授权需人在在线侧确认；界面通过对象状态和控件可用性表达，不设置常驻边界说明块。

| 2 | 贴近业务语言 | 使用案件、策略、实验、任务、证据、注册包，不暴露技术内部术语 |

## 11. 样张验收口径

- 两版使用同一页面、同一内容与同一信息层级，通过 `?theme=dark|light` 替换视觉 token，不设置可见主题切换控件；
- 页面首屏可看到执行结果/状态，而非只有输入框；
- 运行态屏内同时出现对话输入、折叠计划摘要、中断反馈与至少一张结构化结果卡；右栏是实时进度唯一主视图，并显示最新产出、相关对象与能力事实；
- 演示状态通过 `?state=` 直达，不设置常驻七态切换条；待确认等全局状态不在计划卡重复；
- 完整产出使用静态安全 `outputViewer`，支持 Escape 返回且不改变任务运行状态；
- 1200×960 截图宽度不超过 1200px，单张不超过 1MB；
- HTML 可本地打开，主要按钮具备状态反馈；
- 演示页可见“个人作品 · 虚构模拟数据”。

## 12. 当前建议

如果面试场景以讲清产品逻辑、投屏与长时间阅读为主，**优先选择浅色 Paper Ops**；如果更想强化“实时风控 + Agent 调查”的主题辨识度，选择深色 Obsidian Signal。两者都不改变信息架构，选定后只保留一套 token 并铺开其余页面。
