# AI 风控产品 · 从问题到可交互原型

> 一个独立完成的产品作品：把「用 AI 做风控」这件事，从问题定义一路做到可点击的高保真原型。
>
> 所有业务情境、案件、对象、指标与数字均为**虚构 / 模拟**，不代表任何真实系统或上线效果。

---

## 这是什么

一套**面向 AI 风控场景的产品原型**，覆盖「特征 → 策略/模型 → 回测 → 上线 → 监控」的完整闭环，并包含一个**异步深度调查 Agent** 的核心示例。

终点是一个**离线可跑的 HTML 原型**：14 个界面（1 个对话窗口 + 13 个编号页），设计为可演示、可讲通一条完整业务链。

**我想证明的**：不是"我能画界面"，而是「**我能不能把一件模糊的事，拆成可验收的需求，再做到可演示的成品，并管住质量**」。

---

## 为什么做这个

从真实风控工作里带出来的一个判断：**确定性的事情，规则和模型就够；不确定的事情，才需要 Agent。**

所以这个产品的核心张力是——

- **在线**：规则引擎 / 名单 / 模型评分，按版本化阈值**确定性执行**，不冒风险
- **异步**：Agent 做多步取证（定位主体 → 拉上下文 → 比对历史），**不阻塞在线**
- **人**：策略/模型团队在证据链上复核、裁决

这个「在线确定性 / 异步推理」的切分，是整个产品架构的地基。

## 质量是怎么管住的（这部分我最在意）

个人作品容易「做完就算」，所以我在流程里加了几道自缚的锁：

- **判据总账**：一份文件定义"什么算做完"，任何"做完了"必须回到它逐格核对
- **分级授权**：什么能自主改、什么必须报批、什么绝对不能碰，写死
- **冻结契约**：数据 fixtures 一旦冻结，改动要走变更记录
- **三方独立评审**：Codex / Claude / DSH 只读复评，**写者不得自评**
- **门禁脚本**：P0 回归 **77 项**逐条断言，浏览器像素级比对（`different_pixels=0`）
- **变更记录**：只写可机械核对的事实，被取代的旧条目保留不删

**一句话**：我为"做对"花的力气，不比"做完"少。

## 在线看 / 本地跑

原型是**纯静态、离线可跑**的：相对路径、经典 `<script defer>`，无 CDN、无外部字体、无运行时拉数据。

```bash
git clone https://github.com/Yuxin-Shan/ai-risk-pm-portfolio.git
cd ai-risk-pm-portfolio/prototype
open samples/sample-dialog.html        # 对话页（主界面）
# 或直接打开 pages/ 下的任一页面
```

推荐从 **`prototype/samples/sample-dialog.html`** 开始 —— 它是整个产品的入口。
