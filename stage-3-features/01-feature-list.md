> 结论先行:**18 条 FR 全部落到 A 档界面,且全部为 P0。演示必点通的路径有 3 条主线 + 3 处衔接。**

## 一、优先级口径

本轮不设 P2。Demo 的终点是可点击演示,凡是进不了演示的就不该占位。

| 级别 | 判定 | 数量 |
|---|---|---|
| **P0** | 演示主线或衔接点上缺一不可;不做则某条线走不通 | 18 |
| **P1** | 主线可绕开,但缺了会被追问;做出来是加分项 | 0 |

## 三、FR 与优先级总表(逐条)

| 编号 | 功能 | 界面 | AC | 优先级 | 不做的后果 |
|---|---|---|---|---|---|
| FR-01 | 策略规则与阈值查看 | 策略引擎配置 | AC-01 | P0 | 主线 1 起点没有依据,案件为什么被分流说不清 |
| FR-02 | 案件分流与转 Agent(含临时管控) | 策略引擎配置 | AC-02 | P0 | 临时管控不可见,整个"先兜底再调查"的论证塌掉 |
| FR-03 | 实时监控看板 | 实时监控 | AC-03 | P0 | 策略团队没有监控入口,架构上"不逐案介入"落不了地 |
| FR-04 | 看板下钻到案件样本 | 实时监控 | AC-03 | P0 | 数字可解释这条成功标准无法演示 |
| FR-05 | 人工抽检与裁决推翻 | 实时监控 | AC-04 | P0 | 在线 Agent"敢直接裁决"的第三个前提消失 |
| FR-06 | 待人工介入队列处置 | 实时监控 | AC-12 | P0 | 失败分支断裂,只演示成功路径不可信 |
| FR-07 | 对话式需求受理与执行计划 | 对话窗口 | AC-05 | P0 | 工作台主界面不存在 |
| FR-08 | 执行过程的确认与打断 | 对话窗口 | AC-06 | P0 | 对话退化成一次性表单,不是操作台 |
| FR-09 | 新建实验与结果对比 | 实验管理 | AC-07 | P0 | 离线链没有出口依据 |
| FR-10 | Agent 配置 | Agent 配置 | AC-08 | P0 | 打回修改分支无落点 |
| FR-11 | 工具注册与授权配置 | 工具台 | AC-09 | P0 | 在线 Agent 无工具可调,取证链断 |
| FR-12 | 工具调用记录 | 工具台 | AC-09、AC-16 | P0 | AC-09 的"调用记录可按案件查询"与 AC-16 的"证据链与调用记录一致"都验收不了 |
| FR-13 | 离线任务队列与重试 | 任务队列 | AC-10 | P0 | 批量重跑与失败重试演示不出来 |
| FR-14 | 证据链视图 | 证据链视图 | AC-11 | P0 | 三条线共用组件,缺了都无法自证 |
| FR-15 | 验证报告与待注册包 | 验证报告 | AC-13 | P0 | 离线转线上的唯一入口不存在 |
| FR-16 | 在线侧确认注册 | 模型服务 | AC-13 | P0 | 发布路径终点缺失,衔接点断 |
| FR-17 | 日志回放与异常定位 | 日志回放 | AC-14 | P0 | 排查链全断;工作台与在线侧的唯一连接点消失 |
| FR-18 | 在线 Agent 异步取证、裁决与回填 | 实时监控(案件详情) | AC-16 | P0 | 作品的主题能力不被验收 |

**首版把 FR-12 定为 P1,三方评审后升为 P0。** 理由:上游 AC-09 明确要求调用记录可按案件查询,AC-16 要求证据链步骤与调用记录一致。定成 P1 等于承认这两条可以不验收,而且它会成为衔接 ② 的验收盲区 —— 授权生效的最终证据就是"确实调用了、记录查得到"。

18 条不做的后果都是某段流程断裂或某条论证站不住,全部 P0。

## 四、演示必须点通的路径

### 4.1 三条主线

| 主线 | 起 | 止 | 必点通的界面 |
|---|---|---|---|
| 线 1 线上实时链 | 实时命中 | 管控收敛 + 抽检兜底 | 策略引擎配置 → 实时监控(含案件详情)→ 证据链视图 |
| 线 2 离线运营链 | 一句自然语言需求 | 待注册包 + 在线侧确认生效 | 对话窗口 → 实验管理 → 任务队列 → 证据链视图 → 验证报告 → 模型服务 |
| 线 3 异常排查 | 看板发现异常 | 定位到规则 / 工具 / Agent | 实时监控 → 对话窗口 → 日志回放 → (策略引擎配置 / Agent 配置) |

### 4.2 三处衔接(AC-15)

| 衔接 | 从 | 到 | 经过界面 |
|---|---|---|---|
| ① 发布 | 验证报告生成待注册包 | 在线侧模型服务列表 | 验证报告 → 模型服务 → 实时监控 |
| ② 授权 | 工具台注册工具 | 在线 Agent 取证时可调用 | 工具台 → 模型服务 → 实时监控(案件详情) |
| ③ 观测 | 在线日志 | 工作台回放 | 实时监控 → 对话窗口 → 日志回放 |

**衔接 ① 与 ② 的生效动作都由人在在线侧执行**,工作台只生成带编号的待审批包。衔接 ③ 是另一回事:系统只读日志,没有人经手。演示时要让人看见这个"人经手"的动作,它是架构边界成立的证据。

## 五、界面工作量分级

给原型阶段排期用。同一个界面,不同功能的实现量差别很大。

| 界面 | 功能数 | 复杂度 | 说明 |
|---|---|---|---|
| 对话窗口 | 2 | **高** | 主界面。执行计划、待确认卡片、进度回显、证据链嵌入,四个交互机制都要做 |
| 实时监控(含案件详情) | 5 | **高** | 承载 FR-03/04/05/06/18,是功能最密的界面 |
| 日志回放 | 1 | **高** | 时间轴 + 逐案展开 + 筛选,交互机制全新 |
| 证据链视图 | 1 | 中 | 共享组件,但要支持"嵌入对话流"和"独立页面"两种形态 |
| 验证报告 | 1 | 中 | 门禁四项的达成情况要能逐项展开 |
| 工具台 | 2 | 中 | 注册表单 + 授权包生成 + 调用记录列表 |
| 实验管理 | 1 | 中 | 对照组配置 + 结果对比视图 |
| 任务队列 | 1 | 中 | 状态流转 + 重试按钮 |
| 模型服务 | 1 | 中 | 凭包编号调取 + 确认生效 + 列表。**两个衔接点(① 待注册包、② 工具授权包)都落在这一页**,确认/拒绝两套都在这 |
| 策略引擎配置 | 2 | 低 | 规则详情 + 版本切换 |
| Agent 配置 | 1 | 低 | 表单 + 版本记录 |

**高复杂度 3 个:** 对话窗口、实时监控、日志回放。原型阶段的工期主要花在这三个上。

## 六、不做清单

本表列出需要在原型里点明落地形态的 6 条;阶段 2 完整的 8 条“不做”清单见 `../stage-2-requirements/02-prd.md` §3.2。

| 不做 | 原因 |
|---|---|
| 申诉通道 | 真实系统需制度设计(受理、复核、时限),原型不做 |
| 独立的"在线 Agent 管理"界面 | Agent 上线后即为模型服务 / 特征 |
| 移动端适配 | 桌面演示 |
| **界面的视觉规范与设计系统** | 原型阶段不考虑;低保真线框只表达布局与交互 |
| **多角色登录与权限隔离** | 原型不承载组织复杂度;演示中角色用标注区分 |
| **真实数据的导入导出** | 跨边界对象用"人工导出 / 导入"表现,不做文件解析 |
