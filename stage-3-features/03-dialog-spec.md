# 对话窗口交互规格

> 对话窗口是工作台的主界面,也是这次作品里唯一全新的交互形态。本文档把它说透。
> 结论先行:**对话不是聊天框,是操作台。四个机制支撑它 —— 工具选择、待确认、证据链嵌入、产出落地。每个机制都有明确的失败处理。**

## 一、为什么单独写这一份

阶段 2 已经明确:工作台主界面是对话窗口,并且列出了四个必须回答的问题。但那四个问题是**结论级的表格**,每格一句话。真要做原型,每一格都得再展开。

这份规格就是把那四行展开,顺带把界面状态、失败处理、边界说清。

**对话窗口与前 13 个编号界面的关系:** 它是入口,不是替代。每句话最后都落成一个正式对象(实验、任务、报告、待审批包),对象在各自的界面里查看与操作。对话是操作台,不是数据存放处。

## 三、四个核心机制

### 3.1 机制一:怎么知道该调哪个工具

**做法:** 助手 Agent 持有工具台的**工具清单**,每条含名称、描述、参数 schema。收到需求后先**全量语义匹配**(这个 Agent 认识清单里的所有工具),展示前再按“**当前 Agent + 当前版本 + 授权已生效**”逐个标注可用性。

**为什么不先过滤:** 如果把未授权工具直接从候选里剔掉,用户会看到“明明注册过这个工具,对话里却找不到”,也没机会知道该怎么把它接通。所以未授权的工具**继续出现,但置灰不可选**,旁边写明原因和去处。

**为什么必须置灰:** 未授权工具不能进入可确认的执行计划。如果它和已授权工具长得一样,就会出现“选得到但无权调用”,与 AC-09 的权限边界相矛盾。

| 情形 | 表现 |
|---|---|
| 匹配唯一且已授权 | 直接进执行计划,不反问 |
| 匹配到多个 | **反问**,把候选列出来让用户选 |
| 匹配不到 | 明说"没有能完成这项的工具",并给最接近的替代路径 |
| 候选**全部**未授权 | 不反问,直接告知全部候选都未授权,给生成授权包的入口;不承担后续执行 |

**反问长什么样(单选用单选列表,不用复选框):**

```
用户:「把这批案件再查一遍」

工作台:找到 3 个能做这件事的工具,请选一个:
  ○ 关联关系查询(查主体间资金往来)   [已授权]
  ○ 历史交易比对(查该主体历史行为)   [已授权]
  ○ 工商股权穿透查询(查企业股权链路) [未授权] — 去生成授权包
  [选好了]
```

**关键约束:** 没匹配到工具时**不臆造工具名**。计划里出现的每一件事,都对应工具清单里真实存在**且已对当前 Agent 授权生效**的一条。

### 3.2 机制二:执行中途要用户确认怎么办

**做法:** 需要确认的动作在对话流里挂**待确认卡片**。用户**点卡片按钮**或**直接回话**都算答复。

| 触发确认的情形 | 为什么必须确认 |
|---|---|
| 批量重跑(影响面大) | 一次动作波及成百上千案件 |
| 参数有歧义(时间范围、案件类型不明) | 猜错等于整批白跑 |
| 同一需求匹配到多个工具 | 选错工具等于做错事 |

**两种确认形态的分工(避免与执行计划重叠):**

| 形态 | 何时用 |
|---|---|
| 执行计划确认(首次受理) | 需求尚可塑时,给完整计划,可改可确认 |
| 待确认卡片(执行中) | 执行已开始后出现的追加、变更、或影响面大的动作 |

首次受理走计划确认;执行中的追加 / 变更走卡片。

**卡片长什么样:**

```
┌────────────────────────────────────────┐
│ ⚠ 需要你确认                             │
│                                         │
│ 准备对 3,812 笔历史转账案件执行重跑       │
│ 参数:时间窗 上周一 00:00 – 周日 24:00     │
│       Agent 版本 v3(新版提示词)          │
│                                         │
│ [确认执行]  [改参数]  [取消]              │
└────────────────────────────────────────┘
```

**点 `[改参数]` 的反馈:** 卡片原地展开成参数表单,改完点确认,卡片折叠为已确认态,对话流里出现更新后的执行计划。

**直接回话也算答复:**

```
用户:确认

工作台:收到,开始执行。
```

**超时处理:** 卡片挂着不答复时,任务停在待确认,**不会自动往下走**。对话流里保留卡片,方便回头再点。

**方案生成走按钮级确认:** “生成待注册包”在验证报告页由人点按钮触发,不经待确认卡片。验证报告页同时展示样本量与门禁四项达成情况,人在看到这些之后才点,比在对话里点卡片更合理。

### 3.3 机制三:能不能在对话里看证据链

**能。** 证据链视图是**可嵌入组件**,有两种形态:

| 形态 | 用在哪 | 表现 |
|---|---|---|
| 嵌入对话流 | 追问某次执行的取证过程 | 折叠在消息里,点开逐步展开;不跳出对话 |
| 独立页面 | 需要深看、对比、筛选 | 跳到证据链视图,支持筛选与单步深看 |

**嵌入形态的约束:**

- 默认折叠,只显示"证据链 · 4 步",不占屏
- 展开后每步显示:工具名、时间、入参摘要、结果状态
- **证据缺失的步骤有明确标识**(如"名单匹配 — 已跳过(可选工具失败)"),不隐藏、不省略
- 嵌入视图是只读的,要操作就跳独立页面

**这与 AC-11 的关系:** AC-11 验收的是证据链视图作为独立页面可用。嵌入形态是它的第二种用法,两种形态共用同一份数据。

### 3.4 机制四:对话产出的东西怎么落成正式对象

**每次执行都生成对象。** 对话只是入口,对象才是载体。

| 执行内容 | 落到哪 | 在哪个界面查看 |
|---|---|---|
| 建实验跑评测 | 实验 | 实验管理 |
| 批量重查历史案件 | 任务组 + 任务 | 任务队列 |
| 任一次 Agent 取证 | 证据链 | 证据链视图(也可嵌入对话) |
| 验证结论汇总 | 验证报告 | 验证报告 |
| 达到门禁的 Agent | 待注册包 | 验证报告(生成)→ 模型服务(确认) |
| 新注册的工具授权 | 工具授权包 | 工具台(生成)→ 模型服务(确认) |

**右侧对象栏承担"看得见"这件事。** 本次会话产生的对象实时列在右侧,点开跳到对应界面。这样用户不会"说完就找不到了"。

**硬规则:对话不能直接产出生效物。** 待注册包和工具授权包都只是**待审批**状态,生效必须由人在在线侧的点确认。对话窗口里没有任何一个按钮能改变在线侧配置。

## 四、界面状态

| 状态 | 表现 |
|---|---|
| 空态 | 输入框聚焦,下方给 3–4 条示例需求(如"验证新版提示词""回放昨天 14:00 那段") |
| 受理中 | 对话流显示"正在理解需求…",通常一闪而过 |
| 待确认 | 执行计划或待确认卡片挂着,**任务停在原地** |
| 执行中 | 进度条 + 当前步骤描述;可随时插话 |
| 执行被打断 | 已产生结果标注"基于旧参数",不丢弃;暂停标识可见(进度条变灰 + 状态文字) |
| 执行失败 | 说明哪一步失败、为什么;给可执行的下一步(重试 / 改参数 / 换工具);**已完成步骤的产出保留并标注,重试从失败步续跑,可手动选整组重跑** |
| 需求无法受理 | 明说做不到,给替代路径;不臆造工具,不假装执行 |

## 五、边界:对话窗口不能做什么

| 不能 | 原因 |
|---|---|
| 直接写在线日志 | 工作台只读日志 |
| 直接改动实时链配置 | 发布路径必须经人在线侧确认 |
| 直接把模型服务 / 特征 / 策略写进在线侧 | 同上 |
| 调工具清单以外的工具 | 否则"工具可授权"的设计失效 |
| 猜用户意图硬执行 | 歧义时反问,是成功率的一部分 |
