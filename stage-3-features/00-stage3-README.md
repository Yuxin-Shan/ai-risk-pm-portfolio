## 二、线框只画关键帧 —— 这是有意裁剪

阶段 3 的线框用来**把关键路径讲通**,不是把上游冻结的 **14 个界面**(对话窗口 1 + 编号界面 13;A 档 11 + B 档 3)全部画一遍 —— 三张线框合计 17 帧(dialog 6 + monitor 5 + release 6),这是有意裁剪。全量界面画完是阶段 4(可点击 HTML Demo)的活。

| 线框文件 | 覆盖的帧 | 对应界面 |
|---|---|---|
| `s3-wireframe-dialog.svg` | 对话窗口 6 帧(dialog.svg 里编号 S1—S6),不是「七种状态」 | 对话窗口 |
| `s3-wireframe-monitor.svg` | 看板 → 下钻 → 案件详情 → 队列 → 抽检处置 | 实时监控(含案件详情;待人工介入队列是它内部的一个队列视图,不是独立界面) |
| `s3-wireframe-release.svg` | 验证报告 → 工具台 → 模型服务(两份包确认)→ 日志回放 → 分流处置 | 验证报告、工具台、模型服务、日志回放(分流处置是线 3 节拍 6 的处置动作,不是独立界面) |

> 上栏「对应界面」只列上游冻结总账里的界面。线框里的队列、流程节拍等子视图随所属界面一并画出,不单列为界面。

**未出线框的 A 档界面(5 个):**

| 界面 | 为什么本阶段不画 |
|---|---|
| 策略引擎配置 | 结构简单(规则详情 + 版本切换),文档描述已足够;线 1 节拍 2/4 会走到它 |
| 实验管理 | 结构简单(对照组配置 + 结果对比),文档描述已足够 |
| Agent 配置 | 同上 |
| 任务队列 | 结构简单(状态流转 + 重试按钮),文档描述已足够;它是 **FR-13 的离线任务队列**(AC-10),与 `02-key-flows.md` 线 2 节拍 6—7 对应。monitor 线框里出现的是 **FR-06 待人工介入队列**(AC-12),挂在实时监控内,是它内部的一处队列视图,与 FR-13 不是同一套队列,不构成重复。 |
| 证据链视图(独立页形态) | 共享组件。规格定义嵌入 / 独立两种形态(`03-dialog-spec.md` 3.3),但 dialog 线框 6 帧**均未展示证据链**,两种形态的画面都留到阶段 4 |

这 5 个界面在 `02-key-flows.md` 里都作为「必点通界面」或跳转目标出现,节拍表已写明「在哪」,阶段 4 按同一套字段补图即可。

**关于变更记录编号:** 变更记录按**文件各自编号**,同一编号在不同文件里指不同变更。例如 `S3-DR-002` 在本文、`01-feature-list.md`、`02-key-flows.md` 中各有一条,内容互不相同。引用变更记录时必须同时给出**文件名 + 编号**,否则无法唯一定位。本文件编号不连续(缺 S3-DR-003),原因是该轮变更落在 `02-key-flows.md` 与 `03-dialog-spec.md`,本文当轮没有改动。

**关于对话窗口的状态口径(避免「六帧 / 七态」误读):** `03-dialog-spec.md` 第四节定义了 **7 种界面状态**(空态、受理中、待确认、执行中、执行被打断、执行失败、需求无法受理);`s3-wireframe-dialog.svg` 画的是 **6 帧**(S1—S6),对应空态、执行计划、执行中、待确认、反问、执行失败。两者不是「七少一」的关系:S4 待确认卡片正对应规格里的「待确认」态,S6 承载规格里的「执行失败」态;S2 执行计划、S5 反问是规格里没有单列的交互形态。规格里的「受理中」(一闪而过)、「执行被打断」、「需求无法受理」三种状态本阶段未单独成帧,留到阶段 4 按规格补齐。

## 三、三条主线的节拍数怎么算

| 线 | 节拍数 | 算式 |
|---|---|---|
| 线 1:线上实时链 | **18** | 主路径 12 + 工具调用记录 12b + 抽检推翻 13 + 放行分支 7b + 分流层口播 4b + 失败分支 14−15 |
| 线 2:离线迭代链 | **13** | 主路径 11 + 衔接 ① 2 |
| 线 3:事后复盘链 | **6** | 主路径 5 + 分流处置 1 |
| **合计** | **37** | — |
| 衔接 ②(独立演示段) | 4 | 节拍 ②-1—②-4,**不计入上面 37**,演示时当第 4 个独立片段走 |

## 四、三处衔接

| 衔接 | 从哪到哪 | 生效动作由谁做 |
|---|---|---|
| ① 离线验证过的 Agent 回到在线生效 | 工作台 → 在线侧 | **人**(在线侧确认) |
| ② 新取证工具的注册与授权 | 工作台注册 → 在线侧确认 | **人**(在线侧确认) |
| ③ 在线调查轨迹回放工作台日志回放页 | 在线侧 → 工作台 | 系统只读,无人经手 |

## 五、读这套文档的顺序

1. 先看 `01-feature-list.md` 的结论先行与功能表,知道要做哪些事。
2. 再看 `02-key-flows.md` 的三条线,知道这些事按什么顺序演。
3. 对话形态单独看 `03-dialog-spec.md`。
4. 需要视觉依据时看 `diagrams/` 三张线框。
