> 本文档回答:成熟 AI 工作台 / 风控运营台 / 监控台产品,各自在导航、信息密度、对话与后台共存、状态色上有什么可借鉴。

## 一、结论先行:五个产品各借鉴什么

| 产品 | 类型 | 核心借鉴 | 落到本 Demo 的哪些界面 |
|---|---|---|---|
| **Stripe Radar** | 风控运营台 | 规则列表形态(动作+条件+优先级)、案件队列的「列表/详情」两视图、风险分刻度、处置动作按钮组 | 策略引擎配置、实时监控(下钻列表 + 案件详情) |
| **Langfuse** | Agent 可观测平台 | Session > Trace > Span 三层结构、树形轨迹视图、提示词版本化(v1..vN + 标签)、左侧导航分组 | 证据链视图、Agent 配置(版本管理)、日志回放、工作台侧边导航 |
| **Datadog** | 深色监控台 | 深色控制台原则(壳深、图表主导、密度即特性)、状态色只用于状态、分类色板固定顺序、表格数字 tabular、扁平化(边框+色阶,卡片不投影) | 实时监控看板、深色样张的直接依据、全局状态色规范、表格规范 |
| **Linear** | 任务管理 | 默认列表视图、状态分组(Bucklog/Started/Completed/Canceled)、行内状态点与优先级点、ID+标题的紧凑行 | 任务队列、实验管理列表 |
| **同盾风控中台** | 国内风控平台 | 决策引擎(规则/决策流/名单)的分块惯例、策略验证手段的命名惯例(冠军挑战者、灰度发布、决策实验室)、预警处置/案件中心 | 验证「灰度中」「冠军挑战者实验」「名单管理」的界面惯例在本 Demo 中的对应落点 |

**另有一条跨产品形态结论**(见 §四):对话式界面与后台控件的共存,业界有三条路线,本 Demo 按阶段 2/3 既定结论走「对话为入口、对象为载体」路线,视觉上借鉴路线 B 的右侧上下文栏。

## 二、逐个产品

### 2.1 Stripe Radar —— 风控运营台【已考证,官方文档】

**形态要点:**

1. **规则列表**:规则呈 `{动作} if {条件}` 形态(如 `Block if :amount_in_usd: > 1000`);规则按固定优先级求值(3DS → Allow → Block → Review),命中即停。自定义规则建议先在「Review」动作下试运行再转正式「Block」。
2. **Review 队列两视图**:列表视图快速扫单(风险等级、主体、金额、时间);详情视图给出风险洞察(命中因素)与关联记录(同邮箱/IP/卡的其它交易),支持上一单/下一单切换。
3. **风险分刻度**:0–99,默认 65+ 为 elevated、75+ 为 high,分级对应不同处置色。
4. **处置动作组**:Approve / Refund / Refund & report fraud —— 每次处置是明确的按钮动作,处置后案件有明确 closed_reason。

**对本 Demo 的可借鉴点:**

- 策略引擎配置页的**规则表列**:规则名、条件(命中特征)、动作(分流方向)、优先级、版本 —— 与 FR-01/FR-02 的「出示阈值、解释分流」演示目标一致。
- 实时监控下钻的**样本列表 → 案件详情**两视图结构(FR-04);案件详情页的「裁决 + 置信度 + 关联证据」布局(FR-18)。
- 抽检/待人工介入队列的**处置按钮组**(确认/推翻/结案),每个动作后状态徽章立即变化 —— 对应 AC-04/AC-12 的「推翻后管控解除」「结案并移出队列」。
- 「规则先在低风险动作下试运行再转正式」的惯例,对应本 Demo 的**灰度**概念(先灰度、后全量),给「灰度中」状态提供了行业惯例支撑。

### 2.2 Langfuse —— Agent 可观测平台【已考证,官方文档】

**形态要点:**

1. **三层结构**:Session(多轮完整记录)> Trace(单次交互)> Generation/Span(原子步骤:耗时、token、输入输出)。左侧导航即按 Tracing / Sessions / Prompts / Scores / Datasets 分组。
2. **轨迹视图**:点击任一 Trace 看时间线/树形展开的执行步骤,定位慢步骤;支持树形/图两种形态。
3. **提示词版本化**:提示词作为数据管理,每次编辑自动出新版本(v1、v2、v3),旧版本保留可回滚;用标签(production/staging/latest)在运行时指向版本,标签切换即部署。
4. **评测与数据集**:数据集跑评测,评分(数值/分类/布尔)挂到 trace 上;dashboard 出质量/成本/时延指标。

**对本 Demo 的可借鉴点:**

- **证据链视图的树形结构**:一次调查 = Trace,每一步取证 = Span(工具名、时间、入参摘要、结果状态)—— 与 AC-11/AC-16「逐步展示、缺失明确标识」直接对应。
- **Agent 配置页的版本管理形态**:版本列表(v1..vN)、当前生效标签、历史版本只读 —— 对应 FR-10 与打回分支「改提示词生成新版本,旧版本可查」。
- **日志回放页**:按时间段重建可审计决策轨迹,本质是 Langfuse trace 视图的「业务化改造」—— 但本 Demo 只展示日志中实际存在的内容(FR-17),不还原模型内部推理,这条边界比 Langfuse 更严。
- **工作台侧边导航分组**:Tracing/Sessions/Prompts/Datasets 的分组方式,验证了本 Demo 工作台「对话/实验/Agent/工具/任务 + 证据/报告 + 系统」分组结构的合理性。

### 2.3 Datadog —— 深色监控台【已考证:官方深色模式博客 + 设计系统公开整理】

**形态要点(重点是深色控制台的设计原则):**

1. **壳与内容的明暗分工**:营销页浅色、应用内控制台深色(壳深蓝紫 #110617 系),理由是深底让多序列图表更醒目。**「产品即看板:chrome 收缩、图表主导、密度是特性」**。
2. **状态色只用于状态**:OK 绿 / warn 黄 / error 红 / info 蓝,绝不把状态绿挪作普通图例色;图表分类色板固定 8 色并**保持顺序**;图例为右上角小块。
3. **数字排版**:看板/告警/表格上的指标**全局 tabular figures**(等宽数字),数字右对齐;代码/查询用等宽字体。
4. **扁平化深度**:卡片用「边框 + 色阶差」分层,**不用投影**;悬停只变 1px 边框色;4px 圆角;4px 基础间距(4/8/12/16/24/32/48/64)。
5. **表格规范**:行高 28px、发丝分隔线、表头 sticky 大写小号等宽、数字右对齐。
6. **布局**:左导航 200px 常驻,窄屏折叠为 48px 图标轨;看板 12 列可拖拽栅格,瓦片 6/4/3/2 宽。

**对本 Demo 的可借鉴点:**

- **深色样张(监控台版)的直接依据**:壳深色 + 面板色阶分层 + 状态色高饱和 + 图表主导。但主色不用 Datadog 紫,本 Demo 用蓝(见《设计基线》)。
- **状态色规范**:成功/警示/失败/处理中四色只用于状态;业务语义(拦截/放行)与系统状态(成功/失败)共用一个色族,靠上下文区分(§三)。
- **表格与数字规范**全盘采纳:tabular-nums、右对齐、发丝分隔线、sticky 表头 —— 实时监控下钻列表、任务队列、调用记录都会用到。
- 12 列栅格、图标轨折叠:对实时监控看板(FR-03)直接适用。

### 2.4 Linear —— 任务管理【已考证,官方文档 + 公开整理】

**形态要点:**

1. **默认列表视图**:紧凑表格,按状态分组;可切看板视图。
2. **状态是工作流,不是自由标签**:状态归入固定类别(Backlog/Unstarted/Started/Completed/Canceled),类别内可自定义状态名。
3. **行内状态点 + 优先级点**:卡片/行显示 ID、标题、优先级(P0–P3 色点)、项目、标签、处理人;状态色惯例:蓝=计划、黄=进行中、绿=完成。

**对本 Demo 的可借鉴点:**

- **任务队列列表形态**(FR-13):ID + 标题 + 状态徽章 + 优先级点 + 重试按钮,状态流转(排队/执行中/成功/失败/重试中)全程可见。
- **实验管理列表**(FR-09):实验 ID、对照组配置摘要、状态、门禁结果,行内可点进详情。
- 状态归类的思想:本 Demo 的任务状态不自由命名,固定为「排队/执行中/成功/失败/重试中/已打断」六态(见《设计基线》组件清单)。

### 2.5 同盾风控中台 —— 国内风控平台惯例【已考证:官网公开产品页】

**形态要点:**

1. **决策引擎分块**:规则、决策流、策略配置、名单管理、函数库、批量决策 —— 与「策略引擎配置 + 名单管理」两块界面的分块惯例吻合。
2. **策略验证手段命名惯例**:冠军挑战者(champion/challenger)实验、灰度发布、决策实验室 —— 验证了本 Demo「实验(对照组对比)→ 灰度 → 全量」链路的行业命名。
3. **风险大盘**:命中分析、趋势看板、欺诈类型/渠道分析、预警配置与处置、案件中心 —— 看板负责观测、预警与处置分流到专门工作台。

**对本 Demo 的可借鉴点:**

- 「灰度中」作为界面状态徽章有明确的行业惯例支撑(灰度发布是风控策略验证的常规手段)。
- 「冠军挑战者实验」命名惯例 → 本 Demo 实验管理的对照组对比视图(现网冠军 vs 新版本挑战者)。
- 风险大盘「只给信号、下钻定位」的分工,与阶段 2 已定结论一致(归因在排查链完成,不在看板)。

## 三、状态色惯例归纳(跨产品)

五个产品的状态色高度一致,本 Demo 直接采用并在《设计基线》里落地为 7 态:

| 状态 | 惯例色 | 五个产品中的用法 | 本 Demo 落点 |
|---|---|---|---|
| 成功 / 通过 / 放行 | 绿 | Datadog OK、Linear 完成、Stripe approved | 已裁决·放行、任务成功、门禁通过 |
| 警示 / 待人工关注 | 琥珀 | Datadog warn、Stripe 风险分 65+ | 告警、待确认卡片、审批中、待人工介入 |
| 失败 / 拦截 / 拒绝 | 红 | Datadog error、Stripe Block | 任务失败、裁决拦截、注册拒绝 |
| 处理中 / 调查中 | 蓝 | Datadog info、Linear 进行中 | 执行中、调查中、重试中 |
| 灰度中 | 紫(或蓝紫) | 同盾灰度发布、Datadog 分类色板第 8 位紫 | 灰度中、实验对照 |
| 停用 / 未知 | 灰 | Linear Canceled、Stripe 无 | 已停用、排队中、无数据 |

**两点口径:**

1. **红 = 拦截 与 红 = 失败 共存**:拦截是业务裁决、失败是系统状态,两者同用红色族,靠徽章文案与图标区分(拦截用盾牌图标,失败用叉)。这与 Stripe/Datadog 的惯例一致。
2. **琥珀 = 警示 与 琥珀 = 审批中 共存**:两者语义都是「需要人关注」,同色不冲突;审批中配时钟图标。

## 四、对话式界面与后台控件如何共存(跨产品形态归纳)

业界三条路线:

| 路线 | 代表 | 形态 | 适用 |
|---|---|---|---|
| A. 纯对话主导 | Cursor / Claude Code(agent 工作台) | 对话流为中心,其余界面是弹层/侧开面板 | 面向开发者的深度工作 |
| B. 对话 + 侧栏 | ChatGPT Canvas / Langfuse Playground | 对话流占主区,右侧/下侧挂上下文对象面板 | 内容与对象并存的中型任务 |
| C. 对话为入口、对象落盘 | Langfuse(对话产生 trace/session,在各自页面管理) | 对话只是入口,每个产出落成正式对象,在专门界面查看管理 | 企业运营场景 |

**本 Demo 的选择(阶段 2/3 已定,此处只做视觉确认):路线 C 为主,借路线 B 的右侧上下文栏。** 依据:`03-dialog-spec.md` 明确「对话不是聊天框,是操作台」「对话只是入口,对象才是载体」,右侧对象栏承担「本次会话产生的对象看得见」。视觉上:对话流占中主区,右侧 300px 上下文栏(会话对象 + 在线只读概览),左侧导航承接 8 个工作台界面 —— 三栏结构,与 Langfuse 的导航 + 主区 + 详情侧栏同构。

**一句话:本 Demo 的对话窗口视觉目标 = 聊天界面的亲和 + 运营台的信息密度,后者占主导。**

## 五、结论与后续动作

1. 五个产品的借鉴点已映射到 14 界面中的 10 个(策略引擎配置、实时监控、模型服务、实验管理、Agent 配置、工具台、任务队列、证据链视图、验证报告、日志回放 + 对话窗口三栏结构)。
2. 状态色惯例(§三)直接进入《设计基线》7 态徽章规范。
3. 深色样张按 Datadog 的深色控制台原则做,但不复制其紫色品牌与具体数值。
4. 后续动作:把本调研结论交给 Honnold 起草《信息架构与页面流程图》时作为视觉侧输入。
