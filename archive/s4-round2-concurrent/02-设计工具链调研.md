# 设计工具链调研 · 可点击 HTML 原型的实现方案

> 本文档回答:用什么方案把 14 个界面做成「可点击、视觉质量高、能稳定打开」的 HTML 原型。
> 结论先行:**主方案 = 单文件 HTML + 手写 token 化 CSS + 内联 SVG 图标与图表 + 系统字体,零网络依赖**;备选 = ECharts 6(CDN,复杂图表页)、Tailwind v4 browser(CDN,如需极速铺量)。**不用构建工具,每个页面单文件可开。**

| 项 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 上游依据 | 阶段 4 任务定义(原型要能单文件/少文件打开、优先无构建步骤);本 checkout 截图规格(≤1200px / ≤1MB) |
| 调研方式 | 官方文档 + jsDelivr 版本 API 实查(2026-09-17 实查:lucide 1.47.0、chart.js 4.5.1、echarts 6.1.0)+ 方案限制的公开说明 |
| 诚实声明 | 本 Demo 全部数据为虚构模拟数据;引用的库均为开源/公开 CDN,来源见文末 |

## 一、评估维度

选方案按六个维度打分,权重从高到低:

| 维度 | 为什么重要 |
|---|---|
| D1 打开可靠性 | 演示现场、评审、截图三种场景都要一次打开;网络抖动不能毁掉演示 |
| D2 视觉质量上限 | 成品必须明显优于低保真线框(用户的直接预期) |
| D3 14 页一致性 | 14 个界面共享一套组件与皮肤,一处改处处改 |
| D4 无构建/单文件 | 原型要能单文件/少文件打开,不引入 Node 工具链 |
| D5 中文排版 | 全中文界面,字体渲染与行高是观感的大头 |
| D6 迭代成本 | 评审后要按意见改;换皮肤(深/浅)要低成本 |

## 二、样式方案对比

| 方案 | 依赖方式 | 体积 | D1 | D2 | D3 | D4 | D6 | 关键限制(已考证) |
|---|---|---|---|---|---|---|---|---|
| **手写 token 化 CSS(选中)** | 零依赖,内联 `<style>` | ~8–12KB/页 | ★★★★★ | ★★★★(上限高,靠设计能力) | ★★★★★(token 单点改) | ★★★★★ | ★★★★★ | 无库约束,但组件质量完全靠自己做 |
| Tailwind v4 browser CDN | `<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4">` | ~100KB gzip + 运行时编译 | ★★(需联网 + Web Worker) | ★★★★ | ★★★ | ★★★ | ★★★★ | 官方定位「仅原型」;不能 `@apply`/`@layer`;类名必须完整出现在源码里(JS 动态拼接无效);离线即失效 |
| Bootstrap 5.3 CDN | jsdelivr CSS+JS | ~230KB | ★★(需联网) | ★★★(观感「Bootstrap 味」重,难做出差异) | ★★★ | ★★★ | ★★★ | 组件风格已定型,做「监控台感」要覆盖大量默认样式,不如从零 |
| Pico.css 2 | CDN,classless | ~50KB | ★★ | ★★ | ★★ | ★★★★ | ★★★ | 面向文档/轻后台,无表格密度/状态徽章等运营台组件 |
| Shoelace 2(Web Components) | ES Module CDN | 按组件加载,单组件 ~10–60KB | ★★(需联网) | ★★★★ | ★★★★ | ★★★ | ★★★ | 组件全但主题定制靠 CSS 变量,深色皮肤要另配;文件多、依赖链长 |

**结论:** 六维里 D1(打开可靠性)与 D3(一致性)是 14 页原型的命门,手写 token 化 CSS 两项全满分,且 D2 上限不受库风格拖累。选定。Tailwind v4 CDN 列为「快速铺量备选」—— 若后续某页工期紧张可临时引入,但不作为默认。

**手写方案的具体形态(写入《设计基线》):**

- 每页一个 HTML,内联 `<style>`;设计 token 用 CSS 自定义属性(`--bg`、`--surface`、`--accent`、状态七色等)定义在 `:root`,`data-theme="dark|light"` 换皮肤 —— 深浅两套皮肤只是两份 token 值,组件代码一份。
- 组件(卡片/表格/徽章/按钮/时间线/气泡)写成可复制的 class 片段,14 页之间复制即一致。
- 页面间跳转用相对路径 `<a>`,保持「可点击」的完整叙事。

## 三、图标方案对比

| 方案 | 依赖方式 | D1 | 说明(已考证) |
|---|---|---|---|
| **内联 SVG(选中)** | 零依赖,图标路径直接嵌在 HTML 里 | ★★★★★ | 24×24 网格、1.6px 描边、`currentColor` 跟随文字色;约 30 个图标总量 ~8KB;深浅两皮肤自动适配;离线可用 |
| Lucide UMD CDN | `<script src="https://unpkg.com/lucide@1.47.0">` + `lucide.createIcons()` | ★★ | 图标全(1600+),但需联网 + 运行时 JS 替换,截图/演示断网即空白 |
| lucide-static(单图标 SVG 文件) | CDN 逐图标引用 | ★★ | 不加载 JS,但 30 个图标 = 30 个外链,文件碎片化 |
| Iconify API | `https://api.iconify.design/...` | ★★ | 运行时按需取图,依赖其 API 服务可用性 |
| Font Awesome 6 CDN | CSS + webfont | ★★ | 字体图标,描边感弱,与手绘内联 SVG 混用不一致 |

**结论:** 内联 SVG。30 个图标按 Lucide 的几何风格手绘(圆形端点、统一 1.6px 描边、24 网格),但路径自己写 —— 不引 Lucide 文件、无版权依赖、离线可用。需要新图标时补画一个即可。

## 四、图表方案对比

| 方案 | 依赖方式 | 体积 | 适用 | 限制 |
|---|---|---|---|---|
| **手写 SVG 图表(选中为主)** | 零依赖 | 每个 sparkline/柱条 <1KB | 迷你趋势线、状态柱、门禁达成条、对比条形 | 只做静态/轻动画;复杂交互(缩放/悬浮十字线)不覆盖 |
| ECharts 6 CDN(备选) | `<script src="https://cdn.jsdelivr.net/npm/echarts@6.1.0/dist/echarts.min.js">` | ~1MB(全量) | 实时监控看板的多序列曲线、验证报告的对比图,若需真实图例/坐标轴 | 体积大;首屏加载依赖网络;深/浅皮肤需自定义 theme 或动态换色 |
| Chart.js 4.5.1 CDN | `<script src="https://cdn.jsdelivr.net/npm/chart.js@4.5.1/dist/chart.umd.min.js">` | ~200KB | 同上,中等复杂度 | 中文/表格混排风格偏「报表」,运营台感弱于 ECharts |
| ApexCharts | CDN | ~500KB | 不采用 | 体积大,收益不增 |

**结论:** 主用手写 SVG —— 本 Demo 的图表需求(迷你趋势、柱状对比、门禁四项、证据链时序)全是「小图、静态、要好看」,手写 SVG 用 CSS 变量着色,深/浅皮肤零成本适配,且离线可用。**实时监控看板(FR-03)的多序列指标曲线是唯一可能要用 ECharts 的页面**:若最终看板需要 7 个指标的连续曲线,再按此表引入 ECharts 6.1.0 并自定义双皮肤;否则仍用手写 SVG 分时条形/迷你曲线。该决策在看板页开工时定,本表已把 URL 与版本查实。

## 五、字体方案对比

| 方案 | D1 | D5 | 说明 |
|---|---|---|---|
| **系统字体栈(选中)** | ★★★★★ | ★★★★ | `-apple-system, "SF Pro SC", "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`;macOS 演示环境走苹方,零加载 |
| Google Fonts / jsDelivr 中文 webfont(如 Noto Sans SC) | ★★ | ★★★ | 中文字体全量 3–8MB,按需分片也重;离线失效;加载闪变 |
| 拉丁 webfont(Inter 等) | ★★ | ★★★ | 只覆盖西文数字,中文仍回退系统字体,两套字混排不齐 |

**结论:** 系统字体栈。数字排版质量用 `font-variant-numeric: tabular-nums` + `font-feature-settings` 解决(对齐看板数字),ID/编号用系统等宽栈 `ui-monospace, "SF Mono", Consolas, monospace`。中文字重只用 400/500/600/700 四档,避免伪粗体发虚。

## 七、选型总结

| 层 | 选定 | 备选(触发条件) |
|---|---|---|
| 样式 | 手写 token 化 CSS,`data-theme` 双皮肤 | Tailwind v4 browser CDN(某页工期紧张时) |
| 图标 | 内联 SVG,24 网格 1.6px 描边,约 30 枚 | — |
| 图表 | 手写 SVG(迷你图/柱/条) | ECharts 6.1.0 CDN(看板多序列曲线时) |
| 字体 | 系统字体栈 + tabular-nums + 系统等宽 | — |
| 截图 | Chrome headless + sips 压缩 | — |

**一句话理由:原型的敌人不是丑,是打不开。** 零网络依赖意味着演示现场、评审、截图、飞书传图四个场景都不会因为一个 CDN 抖动而翻车;token 化 CSS 保证 14 页一致;手绘 SVG 保证深浅两皮肤零成本切换。
