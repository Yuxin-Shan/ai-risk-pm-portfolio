## 一、设计目标与原则

1. **演示可讲,不是上线可信**(项目最高判定标准):每个界面的每个区块都要能支撑一句讲解词;信息架构服务于三条演示线(在线实时链 / 离线迭代链 / 事后复盘链)。
2. **状态可见性第一**(启发式第一条):灰度中、审批中、失败、被打断、证据缺失,这些状态必须一眼可辨——它们正是演示的判断点台词所在。
3. **诚实标注**:界面常驻「模拟数据」标识,绝不暗示真实生产(见第九节)。
4. **对话是操作台,不是聊天框**:对话窗口按 `03-dialog-spec.md` 三个区域(对话流 / 右侧对象栏 / 输入框)实现;执行计划、待确认卡片、证据链嵌入件都是「控件」,不是「气泡」。
5. **一致性靠 token,不靠记忆**:全部颜色、间距、圆角、阴影走 `tokens.css` 变量,禁止硬编码色值散落页面。
6. **零构建、零运行时 CDN**(见《设计工具链调研》):file:// 双击可开,截图零等待。

## 二、风格方向:两版对照

| 维度 | A 版 · 深色监控台 | B 版 · 浅色业务后台 |

| 参照 | Grafana 暗色(官方 token)+ 观测台惯例 | Ant / Arco 系 B2B 后台 + 阶段 3 线框配色 DNA |

| 密度 | 紧凑:8px 圆角、12px 卡内边距、细发丝边框 | 舒适:12px 圆角、16–20px 卡内边距、柔和阴影 |

## 三、布局与导航(视觉侧输入)

信息架构文档由 Honnold 起草,本基线只提供视觉侧已调研结论,供其引用:

- **顶栏切域 + 左栏切功能**(百炼式双层,调研结论第 1 条):顶栏左侧品牌区,中部**分段控件切换「AI 工作台 / 在线风控」**——域切换本身就是演示叙事点(工作台产包 → 切到在线侧 → 模型服务确认)。顶栏右侧常驻「模拟数据」徽章与值班人。
- **左栏按域列出功能**(一级条目 ≤9 个,调研结论:超出即分组):
  - AI 工作台域:对话窗口、实验管理、Agent 配置、工具台、任务队列、证据链视图、验证报告、数据集管理、日志回放
  - 在线风控域:实时监控、策略引擎配置、模型服务、名单管理、特征发布
- **主视图一律「列表/表格 + 详情抽屉/侧栏」两态**(调研结论第 2 条),不做卡片瀑布。
- **对话窗口例外**:它是操作台,三栏结构 = 左导航 + 中对话流 + 右对象栏(`03-dialog-spec.md` §2),对象栏可收起。

### 4.4 「灰度中」为什么是紫色(自研理由)

调研结论:所有参照产品都未公开灰度态色值,需自研。选紫的理由:①蓝(处理中)、绿(成功)、琥珀(待审批)、红(失败)四色已被既有语义占用,灰度必须是一个**不与任何现有状态混淆**的新色;②紫色在整套风控语义里只此一家,演示时说「紫色 = 灰度中」一句话就讲得清;③暗色模式下发 #B4A3F5 与蓝、绿、琥珀、红的区分度均达标。**若评审有异议,只改 --gray 一组 token 即可全站生效。**

## 五、字体层级

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC",
  "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif;
/* 数字 / ID / 代码:*/
font-family: ui-monospace, "SF Mono", Menlo, Consolas, monospace;
```

| 层级 | 字号/字重 | 用途 | 深色差异 |
|---|---|---|---|
| display | 24–28 / 700 mono | KPI 大数 | 纯白 |
| h1 页面标题 | 20 / 700 | 页面 / 卡片主标题 | 同 |
| h2 区块标题 | 15–17 / 650 | 卡片头、区块头 | 同 |
| body-strong | 14 / 600 | 表内主内容、按钮 | 同 |
| body | 13–14 / 400–500 | 正文、表格 | 同 |
| caption | 12 / 400–500 | 辅助说明、时间戳 | 可下探 11 用于徽章/表内元信息 |
| mono | 12–13 / 500 | 案件号、包编号、指标值 | 同 |

规则:**所有数字、编号、指标值用 mono + `tabular-nums`**;中文字重只用 400/500/600/700 四档;不引入 webfont(见工具链调研第六节)。
