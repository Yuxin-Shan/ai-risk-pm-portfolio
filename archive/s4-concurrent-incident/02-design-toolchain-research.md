# 阶段 4 · HTML 原型设计工具链调研

> 调研日期：2026-09-17  
> 项目声明：本文仅讨论原型实现工具。项目中的业务数据均为虚构模拟，不代表真实生产环境或上线结果。

## 1. 选型结论

样张与后续 Demo 采用：

- **结构与组件：原生 HTML + CSS Custom Properties + 少量原生 JavaScript**；
- **图标：Lucide 线性图标，开发时从官方包挑选，交付时仅内嵌实际使用的 SVG**；
- **图表：需要时按页引入 Apache ECharts，不在对话样张中提前加载**；
- **字体：系统中文字体栈 + 系统等宽字体，不依赖远程字体**；
- **构建：无构建步骤，直接打开 HTML；后续可用本地静态服务器获得一致的模块加载行为。**

原因：这个 Demo 的成功标准是“演示可讲”，而不是生产工程复用率。原生令牌与小型组件层可以精确控制两套风格，避免组件库默认外观，同时保证离线打开与截图稳定。外部库只在它明显降低实现成本时按需引入。

## 2. 候选方案

### 2.1 Bootstrap 5.3.8

- **接入方式**：官方提供 jsDelivr CSS 与 JS bundle，可零构建直接 CDN 引入；JS 不依赖 jQuery，bundle 内含 Popper。[官方快速开始](https://getbootstrap.com/docs/5.3/getting-started/introduction/)
- **体积特征**：完整 CSS + JS bundle 属于“整套引入”，即便页面只用少数组件也会携带未使用能力；可改用 Reboot / Utilities 等拆分构建。[官方内容说明](https://getbootstrap.com/docs/5.3/getting-started/contents/)
- **优势**：文档成熟、可访问性基础较好、折叠/弹窗/下拉开箱即用。
- **代价**：默认视觉辨识度强；要得到高质量业务后台，需要覆盖大量默认圆角、间距和颜色。
- **结论**：作为故障兜底或快速表单页备选，不作为本项目视觉基座。

### 2.2 Web Awesome

- **接入方式**：官方支持 CDN，一组 theme + loader 即可使用 Web Components；也可加载 utilities 与 native reset，无需构建。[官方安装文档](https://webawesome.com/docs/)
- **体积特征**：CDN autoloader 按使用到的组件加载资源；也支持 npm 下 cherry-pick 组件。相比整包框架更适合少文件原型，但首次打开依赖外网与组件动态加载。
- **优势**：组件语义清晰、框架无关、暗色主题和可访问性基础较好。
- **代价**：自定义到两套明显不同的风格仍需理解其 token；CDN 失败会影响核心控件。
- **结论**：若后续复杂弹窗/下拉数量显著增加，可局部采用；本轮样张不引入。

### 2.3 Shoelace 2.20.1

- **接入方式**：可用 jsDelivr 直接加载主题和 autoloader，无构建。[官方站点](https://shoelace.style/)
- **关键风险**：官方已明确 Shoelace 进入 sunset、无活跃开发，并建议迁移到 Web Awesome。
- **结论**：不选。即使原型可运行，也不应从已停止活跃开发的库起步。

### 2.4 Ant Design / AntV

- **接入方式**：Ant Design 组件实现主要面向 React，直接塞进单文件 HTML 会引入 React、ReactDOM 和额外打包复杂度；AntV/ECharts 类图表可以独立按需使用。
- **优势**：中后台信息层级、表格、状态色和可视化规范成熟。其可视化规范强调“先摘要、再筛选、后细节”。[Ant Design 可视化规范](https://ant.design/docs/spec/visualization-page/)
- **代价**：完整 React 组件栈与本项目“直接打开、少文件”的目标不匹配。
- **结论**：借鉴设计规范，不引入 React 组件库。

### 2.5 Apache ECharts

- **接入方式**：官方支持下载单文件或通过 jsDelivr 快速接入。[官方快速开始](https://echarts.apache.org/handbook/en/get-started/)
- **体积特征**：完整构建较大，适合真正需要趋势图、分布图的页面；只显示进度和少量数字时不值得加载。
- **优势**：图表类型完整、交互成熟、暗色主题可配置。
- **结论**：实时监控与验证报告阶段按页引入；对话窗口样张不用。

### 2.6 Lucide

- **接入方式**：可通过 CDN 使用 `data-lucide` + `createIcons()`，也可从包中挑选图标后以内嵌 SVG 交付。[官方仓库说明](https://github.com/lucide-icons/lucide)
- **体积策略**：不引入全量运行时；只内嵌实际使用的十余个 SVG，减少网络依赖和无用体积。
- **优势**：线宽一致、识别清楚，适合高密度工作台；SVG 可继承文字颜色。
- **结论**：选用。图标只辅助识别，状态仍必须有文字。

## 3. 依赖矩阵

| 能力 | 本轮样张 | 后续完整原型 | 依赖方式 |
|---|---|---|---|
| 布局、卡片、标签、按钮、表单 | 原生实现 | 原生组件层 | 本地 CSS，无外链 |
| 图标 | 内嵌最小 SVG 集 | 同上，按需增加 | 来源 Lucide，随 HTML/CSS 本地交付 |
| 折叠、确认、暂停、参数修改 | 原生 JS | 原生 JS | 本地脚本，无框架 |
| 趋势图、分布图 | 不使用 | 监控/报告页按需使用 ECharts | 优先固定版本 CDN，并保留降级占位 |
| 字体 | 系统字体栈 | 系统字体栈 | 无网络依赖 |

## 4. 版本与安全约束

- CDN 必须固定版本，不使用 `latest`；正式截图不得依赖 CDN 是否即时可用。
- 使用外链时记录来源、版本与许可证；不可把第三方品牌素材当成本项目原创。
- 所有交互必须有键盘焦点样式；状态信息不能只靠颜色。
- 原型不得包含真实账号、真实案件或生产指标；源码注释同样遵守诚实红线。
- 若 CDN 资源失败，核心导航、文本、状态和按钮仍应可读；图表区域显示静态降级提示。

## 5. 文件策略

- `prototype/sample-dialog.html`：同一对话样张；默认深色，URL 加 `?theme=light` 切换浅色，确保两版内容与结构完全一致；
- `prototype/sample-dialog.css`：共享结构与两套主题令牌；
- `prototype/sample-dialog.js`：共享交互；
- 不引入 package manager，不生成 `node_modules`，双击 HTML 即可演示。
