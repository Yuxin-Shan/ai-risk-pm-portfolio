# 设计工具链调研:可点击 HTML 原型的实现选型

> 结论先行:**手写 CSS + 设计 token、手写八类核心组件、图标内联 SVG、小图手写 SVG sparkline(复杂图才用 vendored ECharts)、系统字体栈、headless Chrome CLI 截图。** 全链路零构建、零运行时 CDN 依赖,file:// 双击可开,截图零等待。任何「CDN 免构建组件库」都不作主方案——file:// 协议限制 + 国内 CDN 可达性不可赌,双重原因。

## 一、决定全局的技术前提(file:// 三规则)

原型要求「单文件/少文件打开」。file:// 协议下页面 origin 为 `null`,**按规范所有 ES Module 与 fetch/XHR 都被 CORS 拦截**,只有经典 `<script src>`、`<link>`、`<img>` 能工作。因此:

1. 所有依赖必须用 **UMD/IIFE 版本,不能用 ESM**;
2. 数据必须**内联成 JS 变量**(`const DATA = {...}`),不能 fetch JSON;
3. 字体、图标同理,必须内联或本地 vendor。

来源:https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS/Errors/CORSRequestNotHttp

叠加「可能在国内网络环境演示」,结论:**凡是运行时依赖公网 CDN 的方案,都不能作为唯一路径**。评估时「离线 vendor 可行性」权重高于体积。

## 二、CSS 层

| 方案 | 体积 | file:// 可用 | 离线 vendor | 结论 |
|---|---|---|---|---|
| **手写 CSS + CSS 变量 token** | 自定(10–30KB) | ✅ | ✅ | **选定** |
| Tailwind Play CDN v4 | ~271KB JS(未压缩,gzip 未验证) | ✅ | ✅(单 JS) | 不选 |
| Pico.css | v2 约 50KB min(gzip 未验证) | ✅ | ✅ | 不选 |
| Bootstrap 5.3 | 227KB / 33KB brotli | ✅ | ✅ | 备选 |
| Open Props | ~15KB gzip | ✅ | ✅ | 可选用 token 参照 |
| TDesign / Arco / Ant 纯 CSS | 不存在 | — | — | 排除 |

- **Tailwind Play CDN 不选**:v4 地址 `cdn.jsdelivr.net/npm/@tailwindcss/browser@4`,浏览器内 JIT 编译、监听 DOM。三个问题:①运行时编译意味着**截图前必须等 JIT 完成,否则截到裸 HTML**;②脚本挂了页面完全无样式(所有备选里最危险);③jsdelivr 国内不可靠。来源:https://tailkits.com/blog/tailwind-css-v4-cdn-setup/ 、https://factory.ai/open-source-wikis/tailwindcss?page=packages%2Fbrowser.md
- **Pico.css 不选**:classless 语义化干净,但**无 utility、无监控台需要的卡片/表格密度控制**,做 14 个风控界面会大量覆盖重写。
- **Bootstrap 5.3 列为备选**:唯一「体积小 + 交互组件免费」的方案,Modal/Dropdown/Tooltip/Tab/Collapse 全靠 `data-bs-*` 属性驱动,写 HTML 就能点。代价是视觉辨识度太强,且官方 CDN 就是 jsdelivr,国内需自托管。来源:https://getbootstrap.com/docs/5.3/getting-started/download/
- **Open Props 可作 token 参照**:纯 CSS 变量库、MIT、无 JS 运行时。注意 URL 必须显式写版本号(`@12.2.0`),`@latest` 会 404。我们自写 token,只参考它的结构。

**选定理由**:14 个界面共享一套 `tokens.css`,一致性靠 token 约束而非框架;零网络、零等待、100% 截图稳定;改主题 = 改 token(直接支撑两版样张)。

## 三、组件库

| 方案 | 免构建用法 | 体积 | 结论 |
|---|---|---|---|
| Shoelace | autoloader(jsdelivr) | 官方 bundle 体积未验证 | 不选:项目已 sunset,迁移 Web Awesome |
| Web Awesome 3 Free | autoloader,约 70 组件,MIT | 未验证 | 备选(vendor 后可用,接受 FOUC) |
| Element Plus(Vue3 UMD) | unpkg 官方支持 | Vue 128KB + EP 全量 UMD + CSS,1MB+ | 不选 |
| TDesign Vue Next | UMD + `tdesign.gtimg.com` 图标 | 1MB+ | 不选 |
| Arco / Ant Design | React UMD 存在(antd v5 移除 antd.css,样式运行时注入) | 1.5MB+ | 不选 |
| **手写组件** | — | 约 300 行 CSS | **选定** |

- 所有主流组件库的「CDN 免构建」都是官方承认的临时方案,共同代价:1MB+ 体积、运行时代价、**CDN 单点故障 = 整页白屏**(不是样式丢失,是渲染不出来),与「国内网络演示」直接冲突。来源:https://element-plus.org/zh-CN/guide/installation.html 、https://deepwiki.com/Tencent/tdesign-vue-next/7.2-distribution-formats 、https://arco.design/react/docs/start 、https://deepwiki.com/ant-design/ant-design/2-build-system-and-infrastructure
- **选定手写**:风控监控台 + AI 工作台的核心组件只有八类——**卡片、指标块、表格、状态徽章、进度条、开关、侧边栏、Tab**——纯 HTML + CSS 约 300 行覆盖,100% 可控、100% 可截图。交互用原生元素:`<details>`(折叠)、`<dialog>`(弹层)、`[popover]`,免 JS。

## 四、图标

| 方案 | 许可 | 离线 | 结论 |
|---|---|---|---|
| **Lucide 内联 SVG** | ISC,可商用 | ✅ | **选定** |
| Tabler Icons sprite/webfont | MIT,5000+ 图标 | ✅ | 选定(与 Lucide 二选一,取 Lucide 路径更简洁) |
| Iconify API | — | ❌ 需网络 | 降级路径 |
| Font Awesome 6 Free | 免费版 2009 图标 | ✅ | 不选:图标数/体积比劣于内联 SVG,且 FA6 官方已改注册制 KIT |
| TDesign Icons | `tdesign.gtimg.com` 国内可达性好 | 使用时发网络请求 | 不选(有网络依赖) |

- **选定做法**:从 `lucide-static/icons/{name}.svg` 取所需约 40 个图标的 `<path>`,内联成 JS 对象或 `<svg><symbol>` sprite。外层 `<svg>` 自己写,`stroke: currentColor; fill: none; stroke-width: 2` 交给 CSS 控制。README 明确「原型阶段用内联 SVG 是官方认可做法」。来源:https://github.com/lucide-icons/lucide/blob/4f2a6b70d85d92a78ca634ae76c7451150ed7d96/packages/lucide-static/README.md
- 零网络、零字体、currentColor 继承、任意缩放、截图 100% 稳定。
- Iconify API(`api.iconify.design/{prefix}/{name}.svg`)仅作兜底:加载失败只是图标缺失,页面仍可用。

## 五、图表

| 库 | 体积 | 结论 |
|---|---|---|
| ECharts 5.6 全量 UMD | ~1MB | 备用 |
| ECharts common / simple | ~664KB / ~470KB | 备用 |
| ECharts 自定义构建(仅折线) | ~100–150KB | 备用 |
| Chart.js 4.4 | 传输 55–70KB | 不选:类型偏少 |
| ApexCharts | 462KB | 不选:性价比最差 |
| **手写 SVG sparkline** | <1KB | **主方案** |

- **策略:小图手写 SVG,复杂图才动用 ECharts(vendored)。** 一条 30 点 sparkline 就是一个 `<polyline points="...">`,JS 从数组生成 <20 行。额外好处:①零依赖;②**截图不需要等 canvas 渲染**(ECharts 是 canvas,`--virtual-time-budget` 不保证渲染完成);③矢量任意缩放。14 个界面里可能只有实时监控 2–3 个图需要 ECharts。
- **CDN 国内可达性(重要事实)**:`cdn.jsdelivr.net` 国内 2025–2026 基本不可直接用(DNS 污染,多来源持续讨论);unpkg 慢(国外节点);npmmirror 速度最好且内置类 unpkg 解析(`registry.npmmirror.com/{pkg}/{version}/files/{path}`,路径格式与 unpkg 不同);BootCDN 有 2024 年无预警变更地址记录与 2025 年供应链投毒指控(论坛用户指控,非官方结论);cdn.baomitu(360)已基本停服;Staticfile 已停止维护。来源:https://www.cnblogs.com/liangjian103/p/19543369 、https://zhuanlan.zhihu.com/p/633904268 、https://developer.aliyun.com/article/1426614
- **离线 vendor 方式**:`npm i echarts` 后拷 `node_modules/echarts/dist/echarts.min.js` 到 `prototype/vendor/`,经典 `<script src="../vendor/echarts.min.js">` 相对路径引入(file:// 下经典 script 不走 CORS,可正常加载)。

## 六、字体

**选定:系统字体栈,零 webfont。**

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC",
  "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif;
```

- 演示机器是 macOS,**PingFang SC 系统内置**,零体积、零网络、零 FOIT/FOUT、截图零风险;
- 中文 webfont 单文件 3–20MB(思源黑体 16MB+),gzip 后仍有 3–8MB,14 界面 + 频繁截图会毁掉演示体验;
- Google Fonts 在中国大陆多数网络无法稳定解析(`net::ERR_CONNECTION_TIMED_OUT`),镜像可用性随时间变化,默认不用;
- 中文字体的「个性」靠字重字号对比和排版实现;拉丁/数字部分可用系统 SF Mono/Menlo 做 mono 强调。

来源:https://github.com/joeseesun/qiaomu-design/blob/main/references/chinese-typography.md 、https://wpml.org/forums/topic/google-fonts-and-chinese-translation/

## 七、截图工具链(macOS)

**主方案:系统装的 Google Chrome 152 headless CLI,零安装。**

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1440,900 --virtual-time-budget=5000 \
  --default-background-color="ffffff" \
  --screenshot=/path/out.png file:///path/page.html
```

- `--screenshot` 把页面写入指定路径(默认写当前目录 `screenshot.png`);`--virtual-time-budget` 快进定时器;`--hide-scrollbars` 与 `--default-background-color`(不带 `#`、要引号)官方未文档化但实际存在。来源:https://developer.chrome.com/docs/automation-and-testing/headless-cli
- **已知坑**:
  1. `--window-size` 在 `--headless=new` 下曾有被忽略、截图变 1028×653 怪尺寸的历史 bug——**每次截图后用 `sips -g pixelWidth` 验证实际尺寸**,必要时用 `--force-device-scale-factor` 反推;
  2. CLI 只能截视口,不能截整页——**样张与页面按固定视口(1440×900)设计,内容一屏放下**,整页需求再上 Playwright;
  3. macOS 中文字体默认渲染正常(系统自带 PingFang SC,Linux 的装字库问题不存在);
  4. `--virtual-time-budget` 不保证 canvas 渲染完成——又一个「小图手写 SVG」的理由。

**Playwright / Puppeteer:暂不安装。** 本阶段只有 2 个样张页面 + 固定视口设计,CLI 足够;到 14 页面批量截图时再评估(`npx playwright screenshot` 的 flag 写法届时以 `--help` 实测为准)。

**sips 压缩(macOS 内置)**:交付截图规格为宽 ≤1200px、体积 ≤1MB(此前 1.1MB PNG 经飞书图片接口 120ms 超时上传失败):

```bash
sips -Z 1200 shot.png            # 等比缩放到最长边 1200
sips -g pixelWidth -g pixelHeight shot.png   # 验证尺寸
ls -la shot.png                  # 验证体积
```

注意 `-Z` 大写等比、`-z` 小写强制宽高会变形;默认覆盖原图,保留原件加 `--out`。

## 八、推荐组合

| 层 | 选型 | 理由 |
|---|---|---|
| CSS | **手写 CSS + CSS 变量 token**(共享 `tokens.css`) | 零依赖、file:// 直开、截图零等待;14 界面共享一套 token 保证一致性;改主题=改 token |
| 组件 | **手写八类核心组件** + 原生 `<details>`/`<dialog>`/`[popover]` | 约 300 行 CSS 覆盖;交互免 JS |
| 图标 | **内联 SVG**(Lucide 路径,currentColor 继承) | 100% 离线、截图稳定 |
| 图表 | **手写 SVG sparkline 为主**;复杂图 vendored ECharts | 小图免等渲染;大图才付体积成本 |
| 字体 | **系统字体栈**(PingFang SC / SF Mono) | 零体积零风险 |
| 页面组织 | 14 个 HTML + 共享 CSS/JS;单文件用 hash 切换子视图 | 经典 script,非 module |
| 截图 | Chrome headless CLI + sips 验证压缩 | 零安装;规格硬校验 |

**备选方案**:Bootstrap 5.3 本地 vendor(拿整套 `data-bs-*` 交互,代价是视觉辨识度);Web Awesome 3 Free autoloader(必须 vendor,接受 FOUC);TDesign Vue Next UMD + `tdesign.gtimg.com` 图标(国内可达性最好的免构建组件库,但仍需接受 1MB+ 与白屏风险)。

**降级路径**(vendor 做不了时):图标用 Iconify API 兜底(失败只是缺图标,页面可用);图表写 `if (!window.echarts) { 渲染静态 SVG 快照 }`;Tailwind Play CDN 是降级路径中最危险的,**不作主方案也不作唯一降级**。

**实施硬性三条**:所有 JS 用经典 `<script src>`(绝不用 `type="module"`);所有数据内联成 `const DATA = {...}`(绝不用 fetch);所有资源用相对路径。

## 九、无法验证 / 需实机确认的清单

1. 各 CDN 的确切国内可达性——结论来自第三方文章与论坛,**未做实际网络测试**,不同地区/运营商差异大;
2. Tailwind v4 browser 构建的 gzip 体积(仅查到 ~271KB 未压缩);
3. Pico.css v2、Shoelace / Web Awesome 官方包的 gzip 体积;
4. Arco Vue 版 UMD 文件路径、Arco Icons CDN 地址(**完全未找到**);
5. ECharts 各 dist 的 gzip 体积(所列均为磁盘文件大小);
6. `npx playwright screenshot` 的 flag 写法(命令存在,以 `--help` 实测为准);
7. 阿里巴巴普惠体确切授权条款(第三方下载站标注矛盾,以阿里官方渠道为准);
8. Google Fonts 各镜像当前可用性(镜像源变动频繁)。
