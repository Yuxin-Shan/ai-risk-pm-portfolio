> 阶段 4 主控(DSH)主导。本文档回答两件事:成熟产品长什么样、用什么工具链把 HTML 原型做得好看。

## 一、产品参照调研

调研目标:AI 工作台 / AI 运营平台 / 风控监控台三类产品的界面形态,回答四个问题 —— 导航怎么切、信息密度怎么组织、对话式与后台控件怎么共存、状态色怎么规范。

### 1.1 参照产品总览

| 产品 | 类别 | 最值得借鉴的一点 |
|---|---|---|
| Grafana | 深色监控台 | 看板栅格 + 面板 + 状态下钻的「作战室」观感 |
| Datadog | 深色运维台 | 系统性色彩规范(Druids)与事件时间线 |
| Linear | 操作台型应用 | 命令面板 + 键盘优先,「工作台不是后台」的信息密度 |
| ChatGPT Canvas / Claude Artifacts | 对话 + 对象并存 | 对话流与「产出对象」并排,对话里直接操作产物 |
| LangSmith | Agent 可观测 | trace / run 树,证据链与日志回放的直接蓝本 |
| Dify / Coze(扣子) | 中文 LLM 平台 | 中文后台的左栏导航 + 对话/工作流形态 |

### 1.2 逐个拆解:各自可借鉴什么

**(1) Grafana —— 深色监控台的「作战室」观感**

- 深底(近黑灰)、面板卡片用 1px 细分隔、信息高密度排布。
- 状态色与语义严格绑定:绿=正常、黄=阈值边缘、红=告警、蓝=数据/信息、灰=无数据。
- 每个面板可点击下钻(drill-down),「数字 → 样本」的链路是我们的 FR-04 要复刻的。
- 顶部为全局导航 + 时间范围选择,主体是 12 栅格的看板。
- **借鉴**:深色版配色基调、面板卡片层次、指标卡下钻交互、告警阈值可视化。

**(2) Datadog —— 系统性色彩规范 + 事件时间线**

- 官方公开的 Druids 色彩系统([Foundations: Color](https://druids.datadoghq.com/foundations/color))把「数据可视化色 / 语义色 / 中性色」分开管理,可视化色不滥用语义色。
- 告警/事件以时间线形式叠加在指标曲线上,一眼定位「什么时候出的问题」。
- **借鉴**:把「图表色」与「状态色」分层 —— 折线用连续色(蓝→紫),状态点用语义色(绿/黄/红/灰),不混用;日志回放页的「指标曲线 + 事件时间线」形态。

**(3) Linear —— 「工作台不是后台」的信息密度**

- 极简左栏 + 命令面板(Cmd-K),高频动作不靠翻菜单。
- 状态色克制:只在高置信语义处用色(绿=完成、黄=进行中、红=阻断、紫=标签),大面积中性灰。
- 密集但有序:行高紧凑、卡片少阴影、用字重而非色块分级。
- **借鉴**:对话窗口「操作台」气质的克制用色、紧凑节奏;「命令/意图输入」即操作入口的思路与我们的对话式受理同构。

**(4) ChatGPT Canvas / Claude Artifacts —— 对话流与产出对象并存**

- 对话在左/中,产出的文档、代码、表格在右侧并排出现,对话可以继续「改这个产物」。
- 关键:产物是**独立对象**,不是聊天消息;对话是操作它的入口。
- **借鉴**:这正是我们「对话流 + 右侧对象栏」与「证据链可嵌入对话流」的模式 —— 对话是操作台,对象才是载体(对应 `03-dialog-spec.md` 机制四)。

**(5) LangSmith —— Agent 可观测的 trace / run 树**

- 一次 Agent 执行展开成一棵 run 树:每一步的输入、输出、耗时、状态、错误。
- 证据链视图、日志回放、工具调用记录三者的「步骤树 + 逐条状态」形态,直接照它做。
- **借鉴**:证据链视图的步骤树样式(工具名 + 入参摘要 + 结果状态 + 缺失标识)。

**(6) Dify / Coze(扣子)—— 中文后台的形态**

- 左栏按能力分板块(应用/工作流/知识库/工具/日志),与我们的工作台左栏(实验/Agent/工具台/任务队列/…)同构。
- 对话/工作流画布与表单后台在同一个信息架构里共存,切换自然。
- **借鉴**:中文企业后台的左栏导航命名与层级节奏;「对话式入口」与「表单后台」平级并存的定位。

### 1.3 四个问题的结论

| 问题 | 结论 |
|---|---|
| 导航怎么切 | **左侧一级导航(在线侧 / 工作台两区)+ 顶部全局区切换**。工作台左栏按能力板块分(与 Dify/Linear 同构),在线侧左栏按资源类型分(策略/监控/模型/名单/特征)。两级,不再加第三级。 |
| 信息密度怎么组织 | **卡片承载指标、表格承载样本、时间线/步骤树承载过程**。监控页用面板栅格(Grafana),列表页用紧凑表格(Linear),过程页用步骤树(LangSmith)。 |
| 对话式 + 后台控件怎么共存 | 对话流是**入口**,产出落到**独立对象**(Canvas/Artifacts 模式);对话里可嵌入只读组件(证据链),深操作跳独立页面。 |
| 配色与状态色规范 | 见 §1.4。核心原则:状态色与语义严格一一对应,图表色与状态色分层(Datadog)。 |

### 1.4 状态色规范(两版皮肤共用同一套语义)

| 语义 | 状态 | 深色版示意 | 浅色版示意 | 用于 |
|---|---|---|---|---|
| 成功 | 通过 / 已生效 / 已完成 | 绿 | 绿 | 门禁通过、注册生效、任务成功 |
| 警示 / 待确认 | 挂起 / 待确认 / 待审批 | 琥珀 | 琥珀 | 临时管控挂起、待确认卡片、待授权包 |
| 失败 | 失败 / 阻断 | 红 | 红 | 工具失败、任务失败、门禁未过 |
| 处理中 | 执行中 / 调查中 | 蓝 | 蓝 | 进度条、调查中、任务执行中 |
| 灰度中 / 中性 | 待审批 / 待授权 / 停用 | 灰(或紫) | 灰 | 灰度中、待注册、未授权 |
| 信息 | 只读说明 | 中性蓝 | 中性蓝 | 下钻无归因、说明文字 |

> 「处理中」(蓝)与「灰度中 / 待审批」(灰)必须一眼可分:前者是「正在发生」,后者是「等人经手」。演示脚本会点名这几种状态,状态色是自检四关第 2 关「系统状态可见性」的视觉底座。

## 二、设计工具链调研

调研目标:能**直接产出可点击 HTML**、优先**无需构建、可 CDN 直接引入 / 单文件可开**的方案。

### 2.1 候选方案对比

| 方案 | 体积 | 依赖方式 | 深色监控台适配 | 结论 |
|---|---|---|---|---|
| Ant Design(React, UMD) | 大(整套 >1MB) | CDN 引 React + antd | 弱(浅色后台向,深色是补丁) | ✗ 锁定浅色观感,难做作战室风格 |
| Arco / Semi Design(字节) | 大 | 官方 UMD + CDN | 中(有深色,仍偏后台) | ✗ 体积大、仍被后台风格框住 |
| Tailwind(Play CDN) | 运行时编译 | CDN 引脚本 | 可 | △ 可用但不稳,依赖运行时 JIT,不推荐给「可讲」原型 |
| **ECharts 5** | ~1MB / ~350KB gzip | CDN 单文件 | **内置 dark 主题 + 可自定义** | ✅ 监控看板刚需,中文图表事实标准 |
| **Lucide 图标(inline SVG)** | 每枚 ~1KB | 复制 SVG,零外链 | 可(笔画图标两套皮肤通用) | ✅ 中性、轻、无构建 |
| **自建 token 化 CSS(推荐底座)** | 0 依赖 | 内联 CSS | **完全可控** | ✅ 两版皮肤的唯一正解 |
| 系统字体栈 | 0 依赖 | 无 | — | ✅ 免字体 CDN,截图/离线打开不回退 |

### 2.2 选型结论(推荐组合)

**底座 = 纯 HTML + CSS(custom properties 设计 token)+ 少量原生 JS。**
**外链仅 2 个:图表用 ECharts,图标用 Lucide(inline SVG)。字体用系统栈,不引网络字体。**

| 项 | 选型 | 理由 |
|---|---|---|
| 渲染底座 | HTML + CSS 变量 + 原生 JS | 单文件可双击打开;零构建;交互(切页/切状态)原生 JS 足够 |
| 图表 | **ECharts 5**(jsdelivr CDN) | 中文图表事实标准;内置 dark 主题可被 token 覆盖;折线/柱状/桑基/仪表盘全覆盖;监控看板 7 指标 + 日志回放曲线刚需 |
| 图标 | **Lucide**(inline SVG, MIT) | 笔画风格中性,深浅两套皮肤通用;单枚 ~1KB,内联零外链;来源公开 CDN/官方仓库,文档注明 |
| 字体 | 系统字体栈(PingFang SC / HarmonyOS Sans / Microsoft YaHei + Inter / system-ui) | 免网络字体;macOS 原生渲染锐利;数字用 `tabular-nums` 对齐 |
| 组件库 | **不自建不行,但自建轻量 token 化组件** | 两版皮肤(深色监控台 / 浅色后台)用一个库必然顾此失彼;token 系统 + 语义组件(按钮/卡片/表格/标签/进度/时间线/待确认卡)才是唯一解 |

### 2.3 为什么不用现成组件库(Ant / Arco / Semi)

- 三者都是**浅色企业后台向**的设计系统,深色主题是后补的「反色」,做不出 Grafana 式「作战室」的深色监控台观感。
- UMD 引入体积大、与 React 绑定,而一个 14 界面的演示原型用原生 JS 就能点通,没必要背框架。
- 两版样张要求「同一内容、只换风格」—— 这正是 CSS 变量的主场:一套语义 token,两套皮肤值,一个文件切 `?theme=dark|light`。

### 2.4 外链来源声明(公开 CDN,文档留档)

| 依赖 | CDN | 说明 |
|---|---|---|
| ECharts 5 | `https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js` | Apache-2.0,公开 CDN |
| Lucide | 内联 SVG(取自 [lucide.dev](https://lucide.dev/),ISC 许可) | 直接内联,无运行时外链 |
| 字体 | 系统栈 | 无外链 |

> 若演示环境完全离线,ECharts 可本地化单文件(把 min.js 下载进 `prototype/vendor/`),其余零依赖。样张阶段先走 CDN,最终原型打包时再决定是否内联 vendor。
