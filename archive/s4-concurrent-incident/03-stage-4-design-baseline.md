# 阶段 4 设计基线 v0.1（待风格定稿）

> 日期：2026-09-17  
> 状态：样张评审稿；用户选定深色或浅色方向后固化为 v1.0。  
> 作品声明：本项目基于抽象业务场景与模拟数据，用于展示产品流程判断能力；不代表作者曾在真实公司主导、上线或运营该产品。所有数字均为虚构模拟。

## 1. 产品体验目标

界面要让讲解者能在 5–8 秒内回答三件事：**现在发生了什么、为什么停在这里、下一步能做什么**。视觉优先级固定为：结果/状态 > 当前判断 > 下一步动作 > 证据与参数 > 历史信息。

对话窗口不是聊天产品，而是“以自然语言发起、以正式对象承接”的任务操作台。任何会影响执行范围、授权或在线生效的动作，都必须落到结构化卡片或专门页面，不藏在一段回复文字里。

## 2. 美学方向

### 共同骨架

- **风格**：工业化、克制、数据密集；不使用营销页式渐变大标题、漂浮光球或大面积装饰插画。
- **装饰**：有意但节制。层级主要靠底色、细边框、密度和字体权重，不靠重阴影。
- **布局**：严格网格。桌面样张为左导航 / 主工作区 / 右对象栏三列。
- **动效**：功能性。微交互 120–180ms，面板展开 180–240ms；进度变化可动画，状态结论不闪烁。

### 方向 A：深色监控台

- 气质：夜间值守、持续运行、技术可信；适合突出异步 Agent 的过程状态。
- 风险：容易显得“安全大屏”或压暗文本。控制方式是减少霓虹、保持正文对比度、用暖琥珀承担人工确认。
- 记忆点：深海军蓝表面 + 冷青主交互 + 琥珀人工节点，数据区使用微弱网格纹理。

### 方向 B：浅色业务后台

- 气质：清晰、理性、适合面试讲解和白天长时间阅读。
- 风险：容易落入通用 SaaS 模板。控制方式是使用明显的对象轨道、左侧业务域切分和偏方正的组件轮廓。
- 记忆点：暖白纸面 + 石墨文字 + 深海蓝主交互 + 铜橙人工节点。

## 3. 颜色令牌

状态色在两套主题中保持同一语义，但调整亮度与饱和度。颜色不是唯一编码；所有状态必须同时显示文字。

| 语义 | 深色 | 浅色 | 使用规则 |
|---|---:|---:|---|
| 画布 | `#07111F` | `#F4F6F8` | 页面最底层 |
| 一级表面 | `#0C1828` | `#FFFFFF` | 主工作区、侧栏 |
| 二级表面 | `#111F31` | `#F8FAFC` | 卡片、列表行 |
| 主文字 | `#E8F0F7` | `#17212B` | 标题与关键结论 |
| 次文字 | `#91A3B5` | `#637180` | 注释、时间、说明 |
| 边框 | `#24364A` | `#DDE3E9` | 普通分隔 |
| 主交互/处理中 | `#43C6D9` | `#126A83` | 按钮、进度、选中态 |
| 成功 | `#55C995` | `#167A55` | 已完成、已生效 |
| 待确认/警示 | `#F0B45A` | `#A85D12` | 人工节点、超时风险 |
| 失败 | `#F07979` | `#C33E45` | 失败与不可恢复风险 |
| 灰度中 | `#9E9BEF` | `#5D59B7` | 灰度状态专用，不等同禁用 |
| 焦点 | `#FFE07A` | `#1D4ED8` | 仅键盘焦点 |

## 4. 字体与数字

- 中文/UI：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 英文与数字：沿用系统 UI 字体；表格数字启用 `font-variant-numeric: tabular-nums`。
- ID、版本、时间：`SFMono-Regular, Consolas, "Liberation Mono", monospace`。
- 不加载网络字体，避免截图与离线打开时字形漂移。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 20/28 | 650 | 当前界面名称 |
| 区块标题 | 15/22 | 650 | 卡片、对象组 |
| 正文 | 13/20 | 450 | 对话与说明 |
| 控件文字 | 12/18 | 600 | 按钮、标签、导航 |
| 辅助/数据 | 11/16 | 500 | 时间、ID、口径 |

## 5. 间距、网格与形状

- 基础单位：4px；常用间距为 4 / 8 / 12 / 16 / 24 / 32。
- 桌面画布：最小演示宽度 1080px，目标截图 1200px；左栏 192px，右栏 248px，中间自适应。
- 内容卡片内边距：紧凑卡 12px，主任务卡 16px。
- 圆角层级：标签 4px、按钮 6px、卡片 8px、主容器 10px；避免所有元素都做“大圆角胶囊”。
- 阴影：仅浮层使用；常驻卡片以 1px 边框区分。
- 每个视口主模块不超过 7 个，减少同权重卡片堆叠。

## 6. 导航规范

- 一级域标题固定为“在线风控”和“AI 工作台”。
- 当前页面使用左侧 3px 指示条 + 背景变化 + 高对比文字三重提示。
- B 档页面仍可进入，但不出现伪造的复杂引导流。
- 对话页左栏底部可显示最近会话，不与主导航混排。
- 顶部栏只放环境、模拟数据、Agent 版本和全局状态，不承载第二套主导航。

## 7. 组件清单

### 全局组件

- App shell、分组侧栏、顶部状态栏、页面标题、面包屑；
- 状态标签、按钮（主/次/文字/危险）、输入框、下拉、复选、单选；
- 卡片、抽屉、弹窗、页签、折叠、toast、空态、错误条；
- 指标块、筛选条、数据表、分页、时间线、步骤条、进度条；
- “模拟数据”水印/标签、帮助提示、键盘焦点环。

### Agent 专用组件

- 用户需求消息；
- 执行计划卡（待确认/已确认/已更新）；
- 运行进度卡（排队/执行中/暂停/失败/重试中/完成）；
- 人工确认卡；
- 工具候选列表（已授权/未授权置灰/生成授权包入口）；
- 嵌入式证据链摘要；
- 对象引用条（实验、任务组、证据链、报告）；
- 生效边界提示（“工作台不直接写入在线侧”）。

## 8. 状态规范

| 状态 | 必须可见的信息 | 允许动作 |
|---|---|---|
| 待确认 | 影响范围、参数、为什么要确认 | 确认、改参数、取消 |
| 执行中 | 当前步骤、总步骤、预计时间、最近更新时间 | 暂停、追加参数、看详情 |
| 已暂停 | 暂停原因、旧结果保留说明 | 继续、改参数、取消 |
| 执行失败 | 失败步骤、原因、保留的结果、重试起点 | 从失败步重试、改参数、整组重跑 |
| 审批中 | 审批对象、发起人、当前节点、等待时长 | 查看包、撤回（如适用） |
| 灰度中 | 灰度范围、开始时间、观察指标、回滚入口 | 查看监控、回滚 |
| 待人工 | 进入原因、已有证据、积压时长 | 确认裁决、解除管控 |

## 9. 图标与可访问性

- 图标采用 Lucide 风格：默认 16px、1.75px 线宽；导航 17px，紧凑标签 14px。
- 不单独用图标表达状态；失败必须写“失败”，暂停必须写“已暂停”。
- 可点击区域最小 32×32px；主要动作最小高度 36px。
- 键盘焦点使用 2px 外环并留 2px offset；不得用 `outline: none` 取消焦点。
- 正文和控件目标对比度按 WCAG AA 检查；图表也需图例、纹理或文字辅助。

## 10. 文案与诚实边界

- 页面顶栏常驻“模拟数据”；关键数据卡或表格再次标注“模拟”。
- 所有数字写成演示场景数据，不使用“线上提升”“生产验证”“已上线”等措辞。
- 成功状态指“演示流程中的任务完成”，不指真实业务效果已得到验证。
- 对话不得输出不存在的工具、数据集或生产结论；未知处显示“需核实”。

## 11. 样张验收点

- 同一内容、同一结构，仅主题令牌与少量表面处理不同；
- 1200px 宽度内无横向滚动、遮挡或文本截断；
- 执行中状态、模拟数据标识、生效边界、对象沉淀首屏可见；
- 确认/暂停/改参数/证据展开至少四类点击反馈可用；
- 截图宽度不超过 1200px，单张体积不超过 1MB。
