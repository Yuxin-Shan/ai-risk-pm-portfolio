# PRD 骨架：高风险交易调查与处置 Agent（14 章）

> 作品性质声明：个人产品能力作品，抽象业务场景 + 模拟数据，不代表曾在原公司负责或上线该产品。
> 状态标记：`[待填]` / `[草稿]` / `[评审中]` / `[已定稿]`

| # | 章节 | 必须回答的问题 | 验收标准 | 状态 |
|---|---|---|---|---|
| 1 | 一页产品摘要 | 给谁用、解决什么风险、为何需要 Agent、核心价值 | 一页内说清目标用户、场景、价值、风险边界、MVP | [待填] |
| 2 | 问题定义与非目标 | 当前流程哪里慢/不稳/损失多大；本期不解决什么 | 问题与功能分开；≥3 项非目标 | [待填] |
| 3 | 用户与角色 | 调查员/审核主管/商户/安全管理员/审计人员分别要什么 | 每角色有目标、权限、痛点；未访谈标「假设」 | [待填] |
| 4 | 风险对象与业务链路 | 风险主体、风险事件、关键证据、可干预节点 | 画出风险事件链，说明每节点能识别或控制什么 | [待填] |
| 5 | 现状流程与目标流程 | Agent 进入前后，人工/规则/模型各做什么 | 两张流程图可逐步对照；不能只画技术架构 | [待填] |
| 6 | 产品能力与 MVP | 首版有哪些模块，哪些以后再做 | 每项功能对应一个用户问题；Must/Should/Later | [待填] |
| 7 | Agent 工作机制 | 输入、知识、工具、步骤、输出、重试、人工接管 | 能解释为何用 Agent；与规则引擎/RPA/单次模型调用的边界 | [待填] |
| 8 | 身份、权限与高风险确认 | Agent 代表谁、能做什么、谁授权、何时确认、如何撤销 | 角色—动作—权限矩阵；高风险动作不得仅靠提示词约束 | [待填] |
| 9 | 风险决策与人工兜底 | 什么自动执行、什么只建议、什么必须人工 | 每类决策有阈值、责任人、超时、降级路径 | [待填] |
| 10 | 失败与滥用模型 | 幻觉、越权、提示注入、数据泄露、工具失败 | ≥10 个失败/攻击场景 + 预防/检测/响应 | [待填] |
| 11 | 评测与指标 | 如何判断准确、完整、安全、稳定、值得上线 | 覆盖任务效果/业务风险/安全/效率/稳定性；每指标有口径 | [待填] |
| 12 | 上线与运营机制 | 如何灰度、回滚、监控、处理事故、版本变化 | 上线门槛、停止条件、人工接管、复盘责任 | [待填] |
| 13 | 平台化与商业模式 | 如何从单场景变成可配置产品，谁可能付费 | 区分 MVP 与未来平台；商业假设不得伪装成客户验证事实 | [待填] |
| 14 | 路线图与决策记录 | 先做什么、为什么不先做其他 | ≥3 个明确取舍及依据，不是愿望清单 | [待填] |
