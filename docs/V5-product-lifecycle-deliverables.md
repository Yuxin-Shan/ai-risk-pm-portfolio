# 产品全流程与交付物清单(风控 · AI 赋能)

> 作品声明:本清单是个人产品能力作品的一部分,基于抽象业务场景与模拟数据,用于展示产品流程判断;不代表作者曾在原公司主导、上线或运营该产品。既往风控经验仅作为问题理解的来源。
>
> 口径说明:标注「(需核实)」的条目为需要按真实团队规则确认的项;标注「可选」的交付物可按项目裁剪。

---

## 一、总览:两条轴,别混画

| 轴 | 回答的问题 | 形态 | 本清单对应 |
|---|---|---|---|
| **流程轴(时间)** | 从想法到上线,按时间做什么、凭什么进入下一步 | 阶段序列 + 准出门槛 | ✅ 就是本清单 |
| **能力轴(架构)** | 上线后系统稳定运行需要哪些能力 | 分层能力图(V4 三列矩阵) | 对应流程的**第 7 段(运营迭代期)** |

**关键**:能力架构图 = 稳态运行的横截面,不是流程图。两者不能混画。

## 二、阶段序列总表

| # | 阶段 | 核心目标 | 关键动作 | 主导角色 | 准出门槛(gate) |
|---|---|---|---|---|---|
| 1 | **立项与前置核查** | 证明值得做,且**具备可迭代条件** | 场景界定、现状与损失分析、**核查在线版本化/回滚/对账/权限隔离能力**、责任与范围确认 | 产品 | 四项前置能力核查通过;缺失则**只允许隔离沙箱研究**,不进真实灰度 |
| 2 | **需求与指标定义** | 把目标变成可验收的需求 | 场景拆解、角色旅程、需求排序、**指标与口径定义**、责任边界与禁区划定 | 产品 | PRD 与指标口径评审通过;责任人与禁区明确 |
| 3 | **数据与特征基线** | 数据可用、**基线无偏** | 特征开发、标签定义、质量检查、**时间穿越/泄漏检查**、基线冻结 | 数据/算法 | 质量检查 + 时间穿越检查通过;**版本冻结、污染防护就位** |
| 4 | **离线开发与回测** | **离线证明有效**(而非感觉有效) | 候选策略/模型开发、**分层回测**、失败样本分析、独立对账 | 算法/策略 | 回测达标且与基线**可复核比较**;误差可解释 |
| 5 | **上线准备与审批** | 可灰度、**可撤回** | 上线方案、灰度计划、**回滚预案与演练**、变更审批、监控告警配置 | 产品 + 研发/运维 | 审批通过,**且回滚演练留证** |
| 6 | **灰度与扩量** | 小流量受控验证 | 影子验证 → 灰度 → 监控 → 阶段性评估 → 扩量决策 | 发布人/策略运营 | 灰度指标达标;**每次扩量均人工批准** |
| 7 | **运营与迭代** | 形成闭环、持续演进 | 指标监测、样本复核、误差回收、漂移监测、迭代与退役 | 风控运营 | 监控与迭代闭环持续运转;旧版可追溯、可撤回 |

## 四、风控产品特有(与普通 App 的差异)

| 差异点 | 说明 |
|---|---|
| **可撤回是前置条件** | 普通 App 上线即交付;风控必须"**上线前先证明可撤回 + 可对账**" |
| **静默损失** | App 靠用户反馈感知问题;风控漏过用户不会投诉,必须靠**对账与监测**发现 |
| **处置不可逆** | 错误处置(如误冻结)伤害真实用户,故要求**可解释、可追责、可申诉** |
| **分层回测** | 必须分总体/独立对照/风险增补报告,**单一准确率不放行** |
| **时间穿越检查** | 候选特征与评测集共用样本 → 结论作废 |
| **上线后对账** | 处置结果与执行回执对账,失败有确定性降级路径 |

## 五、AI 化(Agent/LLM)新增环节与交付物

| 环节 | 交付物 |
|---|---|
| 任务契约与责任定义 | 《Agent 任务契约》《人工接管规则》 |
| 评测集设计与治理 | 《黄金评测集说明》《污染检查记录》《分集报告》 |
| 版本回归 | 《提示词/模型/工具组合版本回归报告》 |
| 沙箱验证 | 沙箱隔离与影子运行记录 |
| 越权与故障测试 | 《越权/工具故障测试报告》 |
| 可观测 | 《AgentOps 运行看板》《成本配额表》 |
| 发布分离 | **Agent 上线审批 与 策略/模型/名单上线审批,必须分离** |
| 确定性闸门 | 禁"LLM 审 LLM";闸门由确定性代码实现 |

## 六、最容易被跳过的 4 个环节及代价

| 跳过什么 | 代价 |
|---|---|
| 独立对照组 / 总体基线 | 自证偏差、收益虚高 |
| 回滚演练 | 事故时无法撤回 |
| 上线后对账 | 复盘断链、无法归因 |
| 前置能力核查 | 做到阶段 5 才发现无回滚能力,灰度作废或被迫全量 |

**一条硬标准**:**文档存在 ≠ 能力存在**。上线方案不附回滚演练证据、不附对账结果,不应放行。

## 八、面试 3 分钟叙事骨架(供参考)

> 立项靠"**可回滚**"立可信 → PRD 定边界 → 基线定无偏 → 离线评测定证据 → 人工审批定责任 → 灰度定小步 → 运营定闭环
>
> 收尾钩子:**"这条链的每一环,都让 Agent 只能辅助、不能越权。"**
