# P1 交付：问题与边界

> 作品性质：个人产品能力作品。抽象业务场景 + 模拟数据，**不代表曾在原公司负责或上线该产品**。
> 标记约定：`[事实]`=有依据；`[假设]`=待验证；`[真实经历]`=来自既往项目（仅作经验来源，不是本作品结果）。

## 1. 一页产品摘要

**产品名（工作名）**：高风险交易调查与处置 Agent（TrustInvestigator）

**一句话定位**：面向商家/支付机构的风险调查人员，把「多源线索汇总 → 风险判断建议 → 分级处置」串成 Agent 可执行链路，低风险动作自动执行，高风险（冻结/限制/拒绝）必须经授权人员确认，全程可审计。

**目标用户**：风险调查员（一线）、审核主管（决策）、安全管理员（权限）、审计人员（合规）、商户（被处置方，被动接触）。

**要解决的业务问题**：`[假设]` 人工调查一件高风险交易平均耗时数分钟到数十分钟，线索分散在账户、商户、交易多个系统，判断依赖个人经验、口径不一致；高风险处置动作一旦误操作（误冻结/误放行）代价高，且缺少可追溯的授权与审计。

**为什么需要 Agent（而非规则引擎/单次模型）**：`[待 P3 定稿]` 初判——因为任务是多步、需要工具调用（查账户/查商户/查交易/查历史处置）、需要根据中间结果调整下一步，且要与人协同接管；规则引擎无法覆盖长尾，单次模型调用无法完成多步取证与动作执行。

**核心价值**：把分散、依赖经验的调查流程变成结构化、可解释、可审计、可分级授权的 Agent 链路，降低单案耗时与人为口径差异，同时把高风险动作关进「后端权限 + 人工确认 + 审计」的笼子。

**风险边界**：Agent 不最终决定高风险处置；不得仅靠提示词约束越权；所有高风险动作留痕。

**MVP 范围（初稿，P3 细化）**：单场景（商家异常交易调查）+ 低风险自动处置 + 高风险人工确认 + 审计日志。

## 2. 问题定义与非目标

### 2.1 问题（与功能分开）

| # | 问题 | 影响 | 依据 |
|---|---|---|---|
| Q1 | 线索分散在多个系统，靠人工逐个查 | 单案耗时长、遗漏风险 | `[假设]` |
| Q2 | 判断口径不一致，依赖个人经验 | 同类案件结论不一致 | `[假设]` |
| Q3 | 高风险处置（冻结/限制）由人直接执行 | 误操作代价高、责任不清 | `[假设]` |
| Q4 | 处置过程缺少完整审计 | 事后无法复盘与定责 | `[假设]` |

### 2.2 非目标（本期不做）

1. **不做**贷前授信 / 信贷风控产品。
2. **不做**通用 Agent 平台或底层框架；只做高风险应用层。
3. **不做**自动执行高风险处置（冻结/限制/拒绝一律需人工确认）。
4. **不做**多租户商业化平台（本期仅单场景，平台化放 P6 讨论）。
5. **不做**替换现有规则引擎/模型，本作品定位为「在其之上做 Agent 编排与处置」。

## 3. 事实与假设清单（严格分开）

**事实（本作品设定）**
- 本作品使用**抽象业务场景与模拟数据**。
- 场景中风险调查需覆盖：账户、商户、交易三类对象。

**真实经历（仅作经验来源，不是本作品上线结果）**
- 既往稽核 Agent：准确率 85%、执行完整率 70→95%、越权率 15→0%、单案约 5min。

**假设（待验证）**
- A1：单案耗时/口径不一致的量化幅度（待访谈或引用行业数据）。
- A2：风险调查员愿意接受「Agent 建议 + 人工确认」的协作方式。
- A3：高风险动作人工确认不会显著拖慢流程。
